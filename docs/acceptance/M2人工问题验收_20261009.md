# 人工研究问题入口验收

日期：2026-10-09。对应 §2、§5.1/5.4、§8.1、§10；本轮交付人工 question 及独立前端入口。decide 的对象歧义复核、note 类型与客户端命令包装继续在需求缺口中。

## 保存与审核

- CLI `rg question` 和本机令牌 HTTP `POST /api/records/question` 共用后端。明确指定已有项目，输入文字保留前后空白、换行、引号与反斜杠，以工具 rg 的人工载体会话保存程序生成的 JSON 原件。
- 写入实体 question 和统一 entity_version claim，来源 manual、非空 human 身份、审核 confirmed。问题确认与方案采用、发现证据和运行状态互不替代，操作不调用模型，不代替用户填写真实科研判断。
- 原文对象、虚拟来源、事件、字面量搜索、证据、问题和不可变 UUID 回执同一数据库事务提交。原文和回执追加约束有效；事务故障保留待清理的对象文件时，不产生成功回执或半个数据库问题。
- 未指定范围保存 SQL NULL/JSON null。人工问题追加修改明确提交 scope=null 时允许未知；遗漏 scope 字段拒绝，模型 schema 和其他记录的完整范围要求继续执行。
- 默认发生时间为提交时刻；回填时间需明确时区，L0 保留输入的时区写法，结构化发生时间规范为 UTC，入库时间独立记录。

## 重试与边界

UUID 标识一次人工记录意图。相同 UUID 与内容重试，包括成功后丢响应、图版本已变化和两个连接并发提交，返回既有记录及当前版本，只产生一份原文和问题。不同文字、项目、人工身份、范围或显式时间不能复用编号，返回 409；相同文字用新 UUID 可独立记录。旧请求重试不撤销后续人工驳回或人工修改。

新写入的 expected_revision 不一致时事务不写入。HTTP 继续只绑定 127.0.0.1，认证、同源、Host、请求长度及 JSON 约束有效。CLI 通过参数数组测试包含命令替换、反引号和分号的文字，只将它作为资料保存。

正文最多 16000 UTF8 字节，完整生成的 JSON 原件最多 65536 字节。证据按 JSON 路径定位，最多 8000 字节分窗，保持 UTF8 边界与原件摘要；转义文字仍按原始 JSON 字节引用。虚拟来源不当成物理扫描文件，不被健康页报成来源缺失；pass2 覆盖明确排除已显式记录输入，瘦身计数和再提取不调用模型。

## 交付边界

所有输入为合成材料，真实会话、试点原话与密钥未进入 fixture、测试快照或 Git。本机令牌及 CLI 是人工操作的信任边界，human 字段不是操作系统身份认证；Agent 的 MCP 候选接口尚待开发。完整 M2 全量双导入与 kill -9、实际客户端钩子、正式 M1 参考质量和整个 M0–M4 仍未验收。
