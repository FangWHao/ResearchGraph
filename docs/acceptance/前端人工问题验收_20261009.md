## 已验收行为

1. 研究问题首页和空项目均有“新增研究问题”入口。表单明确显示保存项目与记录者，正文按用户输入原样发送，保留前后空白和换行；范围留空发送 `null`，不补造范围字段。保存成功刷新项目与图数据，并打开新的人工确认记录和原文引用。
2. 请求使用实际 `POST /api/records/question`。每次新意图生成独立 UUID，发送前按 UTF-8 实测正文及整条 JSON 大小。空白正文、空姓名、超限、重复范围字段和空范围值不能进入写入请求。
3. 请求忙时阻止重复提交。服务已经写入但浏览器未收到响应时，保持同一内容和请求编号重试，实际返回 `replayed=true` 和原记录，不重复创建问题。正文、范围或记录者变更属于新的意图。
4. 实际另一窗口写入造成 409 时，草稿与意图保留，保存按钮停止提交。用户读取最新版本后仍须主动点击保存，不自动提交；重试保持原意图 UUID，并使用最新图版本。
5. 503 后草稿按项目分别保留，切换项目不会将旧草稿写入新项目。401 回到统一鉴权入口，重新登录后输入和请求编号仍保留，也不自动提交。草稿保存在当前页面内存，本轮不提供关闭页面或整页重载后的草稿持久化。
6. 旧请求延迟成功时刷新数据。只有返回 UUID、当前草稿内容/范围/记录者仍匹配，才清除已保存的同一意图；关闭表单和打开结果另外核对当前项目、鉴权及表单归属。实际验证了“旧请求已写入 → Escape 关闭 → 另一项目草稿 → 切回并输入新问题 → 旧响应到达”，新草稿没有被清除，也没有跳到旧记录；随后新意图归属正确，另一项目未提交的草稿仍在。
7. 人工直接记录的 `entity_version/question` 可在既有修改入口保留未知范围，提交 `scope=null`。模型记录和其他类型继续要求完整范围。追加修改保留旧正文、旧原文引用和替换关系，不覆盖历史。

原文引用显示 L0 JSON 中的原始 UTF-8 窗口，其中换行等字符保留 JSON 转义。验收读取实际高亮窗口，解码后与用户输入完全相等，并对未解码窗口实测 SHA256，与原引用摘要相同；没有改写原文窗口以迎合界面断言。
