## 保存与读取合同

`GET /api/view-state?project=项目编号&user=本机标识`只读同一SQLite快照，返回最新保存编号、原保存时间与条件、当前研究图修订。不同项目和本机标识各自读取，不把姓名当账户鉴权；HTTP继续检查令牌、Host和同源，SQL参数绑定，无缓存。

`POST /api/view-state`需精确提供`project_id`、`user`、`expected_view_id`和`view`。显示参数包括格式版本、项目／双截止／图修订、候选显示开关、原节点位置、阅读视角、显示版本以及单过程组的名称与成员。请求最多65536字节；位置有限且绝对值不超过一千万，缩放0.12至1.5，超限拒绝而不截断。正式审核、采用、证据或运行状态不接受为显示字段。

保存使用事务检查图修订、最新保存编号、项目与完整范围的可见节点／有效版本后追加个人视图。候选隐藏时不能保存候选节点或过程组；未来、迟到、驳回、已替换、其它项目或范围节点均拒绝。中英文范围校核比较字段内容，不依赖排序方式。并发初次保存只有一个成功，另一个返回409；图修订冲突保留旧记录，不自动覆盖。

读取保留旧修订的原视图并给出当前修订；损坏旧JSON或矛盾修订只返回不可用原因及保存编号，不返回损坏正文。用户可以携带这个编号显式保存当前视图；后端不把旧布局转为当前研究事实。前端恢复另按保存条件读齐全部分页并重新执行projectGraph／foldGroup；任何缺页、错修订、不可见版本或折叠条件不符都不能直接应用。

## 稳定编号、备份与整项目清除

实际清除测试发现裸SQLite rowid会被VACUUM重排，原先编号CAS不能保证其它项目不受影响。迁移24将既有rowid原样转为`view_id INTEGER PRIMARY KEY AUTOINCREMENT`，增加项目／标识／编号索引，不读取原文、不改图修订、L0或审核。迁移失败整体回滚，重新打开可继续升级且不重复旧视图。

备份保留所有个人视图，恢复后的保存结果与原库一致。既有整项目清除按project_id删除该项目全部个人视图；其它项目的显示正文、编号和时间保留，只有全局研究图修订沿清除合同变化。随后其它项目仍能以原编号保存；即使个人视图全部删除，新编号也不复用。
