# 已有科研依赖的明确迁移验收

本批接通已产生科研依赖的完整物理片段迁移。当前归属和历史归属另存，原件、断言、审核、原生执行事实与原话证明不改写；迁移不调用模型、不产生科研确认。

## 处理合同

提交核对当前图修订、物理首末边界、原件与观测双截止、范围摘要及预检依赖摘要，并明确包含全部必需原件。目标必须为正式项目；普通无依赖归属仍使用独立入口。必需原件按完整物理记录加入，原生运行、编辑、文件版本、显式人工记录、模型工作集及已登记提取计划与队列共同闭合。处理上下文涉及已登记逻辑会话时一并迁移，不把旧缓存身份的半份输入留在原项目。

来源、提取调度、后处理、L1、文件队列和会话锁保护同一事务。未知布局、引用缺失、运行中任务、预算耗尽、过期修订／摘要或缺少首块拒绝写入。UUID与其他显式操作共用意图约束，同意图重试返回原回执；变更意图返回冲突，前端重新读取实际状态。

迁移33为归属历史设只追加表和明确查询投影。当前提取与读取使用当前归属，双时间查询在已知截止恢复当时的项目、会话和别名资格。规则证明仍在审核当时命名空间核对，目标项目出现同名对象不能回写旧判断。新的队列身份按目标项目权限与遮盖配置复核，原外发许可不随迁移授予。

## 快照、备份与整项目清除

文件版本与工作区快照保留原物理存储身份；有效根目录成员供目标读取，原快照JSON和提交字节不变。清除原项目时，另一项目仍引用的记录和字节保留；必要外键容器改为无名称来源占位，并从项目列表隐藏。

共享Git仓库只保留现存快照的确切提交、树和文件。浅边界阻止旧父提交重新携带已删除内容；过期引用与日志及不可达对象清理后核对完整性。清理中断保留等待恢复状态，恢复幂等；最后一份资料删除时回收物理容器和仓库。固定案例实际核对目标提交仍存在、旧独占blob确实返回missing、只剩保留提交、备份可读取、最终仓库消失。

Windows备份不复制正在持有的仓库运行锁，仍复制全部真实快照资料。最后清除已选择的Git打包普通文件时，仅解除其只读属性；重解析点、其他权限失败仍拒绝并保留恢复入口。影子快照2秒预算不改。
