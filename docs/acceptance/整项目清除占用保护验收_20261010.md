# 整项目清除的占用保护

依据执行版 §2、§6.8、§11、§15，用户已选定整项目清除。本次落实清除前需要的进程占用保护；尚未提供删除入口，不把项目遮盖配置或取得锁称为隐私清除完成。

## 行为

- 每个 Store 从打开到关闭持有共享占用锁；只读和写入连接可以共存。打开数据库失败时关闭连接并释放锁。
- 清除执行器将需要同一数据目录的独占锁。已有任意项目的连接、钩子、快照或备份目标写入都会使独占请求立即失败；不强杀进程，不依赖 PID 文件，不等待持有者结束。
- 钩子处理、spool 普通和超大输入写入、手动快照及快照发布也持有共享锁。嵌套调用正常；持有者退出后由系统释放。钩子遇到占用仍退出 0，只记时间、阶段及错误类型，不记录输入。
- SQLite 备份的源 Store 已被保护，备份目标从复制数据库到验证对象、影子仓库和发布 manifest 全程被占用。
- 本机 HTTP 的读取和写入遇到占用返回 409。鉴权、同源校验、正常查询、L0 只追加和模型候选限制保留。

## 验证范围

固定案例使用临时合成数据和真实独立进程，检查并行普通连接、独占冲突、强杀后的自动释放、目录别名、构造失败、拒绝后的数据完整性、真实钩子退出及真实 127.0.0.1 HTTP。备份目标在复制过程中由另一个进程尝试独占，必须被拒绝。

POSIX 使用目录描述符的共享/独占 flock，保护不创建只读目录元数据。原生 Windows 使用 LockFileEx 的共享/独占字节区间，写入口初始化空锁文件；旧目录需先经写入口初始化，读取不创建锁文件。Win32 实现依据 [Microsoft LockFileEx 文档](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex)，本轮只验证 WSL/Linux，不宣称原生 Windows 已通过运行验收。

## 剩余工作

清除仍需只读归属清单、共享对象引用核对、原件及派生数据库行删除、FTS/SQLite 页整理、对象/概览/spool/快照清理、只保留无原文清除记录、中断恢复和旧来源再次导入的处理。单个数据目录独占不等于完成这些动作，也不能阻止其它软件直接打开数据库或改动目录。

备份与导出副本的边界已向用户提问，尚未获得选择；本轮不删除真实资料，不自动搜索并清除外部副本，也不修改 Claude/Codex 日志或研究工作区。
