# M1 提取监控与调用历史验收

日期：2026-10-09。范围：§2、§7.10 与 §10 的 health CLI。完整 M0–M4 与 Atlas 真实效果验收仍未完成。

## 结果

数据库版本 4 新增调用尝试账本。每次实际尝试保存预算、发送前实测、实际用量、发送尝试标记、状态与结束原因；重试不覆盖已结束的旧尝试，缓存命中不新增尝试。最终状态使用本次尝试的显式 ID，已验证两个 worker 交错时不会互相改写尝试状态。这不代表完整并发队列调度已完成。

`rg health` 新增项目、UTC 日期、每日上限和缺口分页参数。每日额度保持全库统计，上限取本次参数，应与 worker 一致。覆盖缺口带事件 ID、会话与阶段，不包含原文。实际用量未知时列出未结算发送尝试，保守预留继续保留；缺少结束记录不能证明进程仍活着，旧运行缺少账本时不补造历史。

利用率用实际输入，缺失时用发送前实测输入；pass1/pass2 的高利用率片段按项目与片段 ID 去重，不将重试重复计作新片段。超过 80% 预算的片段占比严格大于 10% 才报警；校验拒绝率严格大于 5% 才报警，引用失败另列。分母缺失时返回 null。费用采用 §7.10 的每日 token 额度，不计算货币金额。

## 合成接口实测

```bash
uv run python scripts/smoke_derived.py --key-file api_key \
  --output docs/acceptance/deepseek_monitor_final_smoke.json
```

命令退出码 0。仅直接构造两条合成候选，没有发送 Atlas 真实资料。最新[接口结果](deepseek_monitor_final_smoke.json)与[模型输出](deepseek_monitor_final_smoke_model_outputs.json)保留如下事实：

| 阶段 | 发送前实测输入 | 实际完整输入 | 实际输出 | 状态 |
|---|---:|---:|---:|---|
| 链接 | 911 | 891 | 230 | ok |
| 概览 | 695 | 675 | 326 | ok |

1 对链接返回 none，0 条关系、0 个失败，缓存通过；概览 1 页。尝试账本仅有 2 次发送，均结束为 ok；已知输入 1566、输出 556，总用量 2122，与每日计数一致，未结算尝试 0，全部 claims 为 candidate。

健康输出保留了 6 个覆盖缺口：脚本直接构造候选，只调用链接和概览，没有执行两个种子事件的 slim/pass1/pass2。它们不能因链接和概览成功就被标为覆盖。该测试不是提取找回率或引用成功率验收。

早期顺序接口记录也保留在 `deepseek_monitor_smoke.*`：当时用量为 2083，后续补齐显式尝试 ID 与片段去重；最终结果以上述新记录为准。
