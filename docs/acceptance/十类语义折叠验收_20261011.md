## 独立预期与输入

`fixtures/golden/semantic_cases.json` 保存十类、十一场景的公开合成输入和独立写定的预期。A04 分成必需输入与证据综合两个项目。预期明确成员、入口、出口、完整节点数、内部和边界关系、保留历史、采用和证据状态、端口必要性及未选比较角色。预期不通过产品的 `projectGraph`、`foldGroup` 或搜索可折叠子图生成。

`tests/semantic_cases.py` 将这些输入写成小型 Claude／Codex 原生格式，再调用实际扫描器；人工合成断言只追加。运行时身份清单仅关联项目、实体／完整范围、断言、事件、字节窗口与引用摘要，不计算折叠预期。浏览器专用临时服务保存 `.cache/semantic-cases-index.json`，不增加生产 API 或修改默认项目。

| 场景 | 要保留的语义 | 原生或执行入口 |
|---|---|---|
| A01 提出、拒绝、再次采用 | 当前采用，三个决定仍可查原文 | 明确合成事件与完整 L2 页 |
| A02 仅回退代码 | 方法继续采用，补丁报告不冒充物理版本 | Codex 原生补丁开始／结束及 L1 派生 |
| A03 暂停方案、保留阴性 | 暂缓与关键阴性分别保留，主题边只检索 | 独立方法与发现、原文入口 |
| A04 必需输入 | B、C 的命名端口均必需 | 实际完整汇合；漏选分支起点时拒绝多入口折叠 |
| A04 证据综合 | 两份材料保留，不推断独立性或必要性 | 同一菱形结构，显式综合语义 |
| A05 比较后只选 B | 未选 C 继续作为比较端口，不能变成使用 C | 显式 `compare_then_select`、选择和拒绝事件 |
| A06 相同文字、不同条件 | 同对象两个完整范围分别采用／拒绝 | 同身份跨范围版本与关系 |
| A07 消息镜像与压缩 | 原事件保留、瘦身仅出现一次、压缩回放排除 | Codex `event_msg`／`response_item` 镜像、压缩边界、再次导入 |
| A08 工具缺少返回 | 请求存在，退出码和结果未知，不补造失败或阴性 | Codex 原生工具请求、实际 L1 派生 |
| A09 旧会话迟到 | 入库晚不改写更晚发生的采用，双截止各自有效 | 先保存当前决定，再实际扫描旧会话；不回填记录时间 |
| A10 人工纠正后换模型 | 旧候选仍是原行，新候选不能覆盖人工暂停 | 两个离线提供方经真实 Worker 重提取同一事件窗口、缓存复查与人工 edit |

A10 使用本地 `cl100k_base` 精确计数；两次实际 Worker 的 pass2 输入事件相同，计数为正且预算内。模型身份和任务键不同，两份固定输出经实际校验及候选写入入口。相同配置重试不再生成。原行 `claim_state=candidate` 不改，人工 edit 后旧行有效状态为 `dismissed` 且被替代，人工暂停为 `confirmed`，新输出继续 `candidate` 并显示与人工记录的差异。固定离线输出不代表 DeepSeek 的真实提取质量。

每个场景核对完整 HTTP 断言与引用页、每条原话的 UTF-8 字节范围和 SHA256，以及历史 ZIP 的同一语义图。读取前后的库转储一致。A02／A07／A08／A09／A10 另有原生事实专项。没有读取完整真实会话、调用远程模型、执行记录中的命令或删除真实项目。
