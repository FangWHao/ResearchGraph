# 人工决定、对象检索与歧义选择验收

日期：2026-10-09 开始，2026-10-10 收尾。对应 §2、§5.1–5.4、§8.1、§10。本轮提供可选的人工补记与纠错；默认使用仍依靠自动采集与提取。

## 记录与四状态

CLI `rg decide accept|defer|reject|withdraw` 与本机令牌 HTTP `POST /api/records/decide` 共用后端。对象和理由原样保存，动作规范为 accepted/deferred/rejected/withdrawn。已有有效对象按项目及完整范围解析；精确 ID 优先于同名标签，标签需完整相等。人工确认优先取版本，已驳回及已替换的对象版本不参与解析。

唯一对象直接追加 manual/human/confirmed 的 decision_event。确认决定不确认目标 entity_version，不补证据成立或运行成功。省略范围保留 SQL NULL/JSON null，范围含 unknown、未知、未确定、不详、unspecified 或 ? 时也不判断当前采用。前端与模型工作集都保留未知，模型 schema 没有放宽。旧模型决定经人工修改后仍保留原 speaker/explicitness，不误套直接人工原话 schema，连续再次修改已回归。人工追加修改可补完整范围，原文与旧记录不变。

同名或找不到对象时保留 target=null、referent_unique=false 的 candidate。decision 实体仅承载项目归属，没有 entity_version，不能冒充一个新增方案。统一队列返回 pending_decision 元数据；普通确认、跨页批量确认和通用编辑拒绝未解析对象。数据库另有 null 目标确认保护，批次失败不提交其他记录。

## 选择对象与可追溯性

对象选择仅允许现有、有效、同项目且与原完整范围相等的实体；原范围未知时不填入目标范围。请求不允许更改动作、理由或范围。重新验证原决定原文和证据摘要，追加 confirmed 替换版、人工 edit 审核及选择原件。新决定保留原发生时间，选择事件有自身发生/入库时间，两份原文证据均可打开，原 candidate 保留并标为已替换。

GET `/api/decision-targets` 与 CLI `decision-targets` 在全项目有效版本上进行字面匹配，随后按实体分页，页长最多 200。图的 2000 条上限不作为唯一性依据。8000 UTF8 字节标签预览有完整字节数和截断标记，仍按完整标签搜索。固定案例用 2002 个对象验证上限外的同名仍形成歧义，并能选择最后一个对象；另以超过预览范围的人工标签验证末尾搜索。

原件 JSON 最多 65536 字节，选择器 4000 字节、理由 16000 字节；引用通过 JSON 路径定位，8000 字节分窗并保持 UTF8 边界。回填发生时间保留原始时区写法，结构化时间规范 UTC，入库时间独立记录。虚拟 rg 输入继承显式记录排除，不成为物理日志来源，不再次调用模型。

## 重试、事务与恢复

问题、决定与对象选择的 UUID 跨操作检查，含项目、内容、身份、范围和原始回填时间的意图不变才可重放。版本过期的相同意图仍返回原回执；不同内容或操作返回 409。并发同意图仅生成一份原件与记录，已选择对象只能生成一个替换版。旧重放不撤销之后的人工驳回或修改。

BEGIN IMMEDIATE 中原件索引、字面搜索、引用、claim、审核与回执原子提交。故障可留下未引用对象文件，但数据库不产生半份成功记录。备份恢复原始决定、选择原文与回执，删除原对象目录后仍可核对和重放。回执不允许 UPDATE/DELETE，L0 与 claims 继续只追加。版本 9→10 失败整体回滚，旧问题回执和原始事件不变，重新升级仍能重放原问题。

## 交付边界

开发只使用合成记录，不读完整真实会话、不调用远程模型、不安装钩子、不改个人客户端设置。本机 CLI 与访问令牌是人工入口信任边界，human 字段不证明操作系统身份。note 类型仍等待明确规格，客户端包装与 Agent MCP 候选入口另待实现；真实自动完成比例、正式 M1 参考质量和完整 M0–M4 尚未验收。本轮可选人工入口不作为零人工使用已达成的证明。
