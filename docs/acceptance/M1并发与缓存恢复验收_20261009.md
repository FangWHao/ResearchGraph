# M1 并发与缓存恢复验收

日期：2026-10-09。范围：§2、§7.6–§7.10，重点为会话顺序、重复任务与响应持久化。完整 M0–M4 和 Atlas 真实效果门槛仍未完成。

## 行为与证据

同会话提取全程互斥，同项目概览和同模型任务分别使用非阻塞系统进程锁。竞争在计数前结束，既不再次生成，也不改写在运行的尝试。数据库写事务不覆盖远程请求：首个 worker 的生成被测试事件阻塞时，另一连接可导入新的事件，并完成另一个会话的提取。同项目概览竞争保持原有导出文件，另一个项目可正常生成概览。

完整通过 schema 的输出与 validated 尝试状态原子提交。关闭连接后重新打开，服务模拟离线仍能取得该响应，不重新计数或生成；随后严格校验引用。两个连接同时提交相同响应时，一个新增 2 条 candidate，另一个新增 0 条；数据库仅有 1 个对象、2 条候选、2 条证据引用、1 次模型尝试，日用量 30。不同有效输出不能复用成功运行，错误后续引用也不能改写成功状态或图版本。

POSIX 子进程在生成开始后被终止，存活期间竞争被拒绝，等待实际退出后能重跑原会话。原尝试保留 pending、sent=1、未知实际输入和缺失结束时间；后续两次调用成功。日额度保留原 4010 预留及新增已知用量 60，合计 4070；候选只有 1 条，覆盖缺口为 0。锁文件仍存在，恢复依靠系统释放而不是删锁或猜测年龄。

上述数字来自测试提供方，仅用于断言并发和账本行为，不是生产 token 估算。测试不联网、不读真实历史、不发送 Atlas 材料；本轮没有新增收费接口调用。先前 DeepSeek 合成接口记录继续保留。

新增 7 个固定案例，覆盖任务竞争、响应恢复和原子入库、不同会话与采集并行、进程终止后恢复及未知费用、忙时保留覆盖而不建人工失败、项目缓存隔离、概览竞争与独立发布、响应缓存仍需验证原文。两个旧复核测试现在为不同结果建立独立运行；交错监控用例使用两个不同任务，继续验证显式尝试 ID 的归属。

## 边界

没有新增数据库版本；互斥文件保存在数据目录的 locks 子目录。Linux 进程终止案例通过，Windows 锁分支尚未实机验收。全队列守护调度、任务租约和自动接管尚未实现；此恢复案例不是 M2 的全部采集 kill -9 验收。旧成功运行没有输出快照时拒绝判断重复，不补造历史。完整 §15 及真实提取质量仍需后续验收，尚不进入界面开发。
