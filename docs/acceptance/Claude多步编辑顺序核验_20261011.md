# Claude 多步编辑顺序核验

本轮覆盖执行版 §2、§6.2、§8.3、§9 的本地编辑记录、差异与研究图读取。修复的触发条件是：保存的 MultiEdit 请求含无效中间步骤，但工具报告给出可严格重建的最终补丁。旧实现会保留双侧候选；修复后不生成当前后候选，保留前文、补丁和可定位的缺口。

## 输入依据与实现边界

顺序合同来自[Claude Code 官方历史发布包 1.0.103](https://www.npmjs.com/package/@anthropic-ai/claude-code/v/1.0.103) 的 `sdk-tools.d.ts`：`edits` 至少一项，按顺序作用于文件，每项带旧／新字符串及可选 `replace_all`。只下载发布包并核对官方元数据 SHA-512 完整性，未安装或执行其代码。归档 SHA-256 为 `d2dd7d5caa8ea2bf87ff3ac10fdaf7512ed2f75eee5af7eee25f390f4a7c5a34`；下载与类型证据留在忽略缓存中。

新输入仍从原生 Claude JSONL 扫描、实际 L1 队列和严格结构化补丁进入。请求替换在每步核对当前正文的匹配次数；含歧义且未明确全部替换、字段不支持、缺失匹配及最终正文不一致都留下缺口。中间结果按精确 UTF-8 长度限制在既有五百万字节上限内，不用字符除四，不调用模型。原有 Edit／Write、工具错误、未知前文和用户同时修改规则保留。

旧记录诊断在实际 L1 后台派生阶段读取具体原请求与同一行引用的已存候选版本，不扫描完整会话，不打开当前研究文件。无正文的核验结果追加在 `edit_request_checks`，算法版本及原引用元数据摘要限定缓存输入，图查询和默认历史导出保持只读元数据；未完成后台核验的旧记录显示待核验缺口，后版本未知。新待核验项优先于旧不可用项的显式重试，每批每项只尝试一次；对象恢复后 `derive-l1 --retry-failed` 追加新的诊断，旧诊断不改写。

匹配时仍为工具 UTF-8 候选，未核对真实物理字节。请求不一致或不可核验时，`after_version=null`，原编号仍在 `reported_after_version`，旧行及对象保留；当前差异只显示已知前文。图的后版本关系保持未知，导出的原报告候选继续保留。历史图先筛原请求、结果、编辑的发生／已知双时间；核验缓存是原材料的确定性计算，不作为当时新增研究事实。历史证据原窗口维持已有合同，不混入当前 L1。

迁移 25 新建诊断表和追加约束，在有旧 MultiEdit 的库中只增加一次图修订，原记录不变；没有此类记录不增加修订。失败整体回滚，升级不读取原文。后台追加诊断与修订原子提交，备份与整项目清除覆盖本项目诊断，其他项目保留。请求或候选对象缺失、摘要损坏时当前差异明确不可用，不能恢复双侧差异；图上既存诊断仅表示此前核验结果，不证明正文此刻仍可读取。

## 固定案例

公开合成输入在 `tests/multiedit.py`。四个浏览器场景分别为有效顺序依赖与全部替换、新请求不一致、旧双侧候选请求不一致、旧请求缺失编辑数组。旧分支在测试扫描期间精确模拟修复前保存流程，仅用于生成历史不可变行；随后恢复生产派生函数，由真实 API 计算诊断。固定预期在测试中独立写定，不由产品校验器生成。

后端核对无效中间步骤、逆序、非数组／空数组、非字符串字段、布尔类型、重复匹配、最终不一致、Unicode／CRLF／U+2028、重叠顺序替换和中间扩张上限。旧对象删失或损坏、错误项目／调用／阶段引用、双时间隐藏、只读重开、重导入及队列幂等、独立备份恢复、原生证据／图／ZIP 一致、升级失败回滚和只升一次均有固定断言。后台核验中断整体回滚、诊断禁止更新／删除、图和默认导出禁止对象读取、批次优先顺序、恢复对象后追加重试及整项目清除亦有固定断言。只读前后逐表数据库转储及修订保持一致；后台追加诊断才会增加图修订。
