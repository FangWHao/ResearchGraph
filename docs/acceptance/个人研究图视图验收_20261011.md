# 个人研究图视图界面验收

本轮基线为 `eb3eb2b`。前端只修改本轮允许的十个文件，父任务负责后端、总文档、完整浏览器及发布。开始前已核对进度末四十行、原则与界面章节、原设计书第七节及完整研究图决定；改动前副本独立解包逐字一致。

个人视图沿已有复核者姓名和项目区分。姓名只是本机显示标识，不是账户鉴权。用户主动保存完整登记图的原节点位置、显示版本、一个过程组和视角；研究信息不写入浏览器持久存储。原文、审核、采用、证据与图修订不由此改变。

读取保存记录后，界面先固定其项目、修订和两个时间截止，重新读取全部研究记录，再核对可见版本、全部原节点及折叠拓扑。保存记录不含边、证据或正式状态。布局尚未就绪、分页未齐、异常图或阅读条件已修改时不能保存；请求超过六万五千五百三十六个 UTF-8 字节时明确拒绝，不截断。过程组拖动只更新入口原节点的位置，展开保留其余原节点位置。

保存使用最新视图编号比较；其它页面已保存或研究图修订已改变时，保留旧记录并提示冲突，必须主动读取或重新读取图后再决定。项目、姓名、页面、截止或刷新身份改变会停止页面等待；迟到成功或鉴权失败不会替换新身份的布局或使其登出。取消页面等待不承诺服务端没有保存，用户可主动读取回执。

独立浏览器服务使用端口 `9802` 和临时合成库。准备阶段调用现有完整研究图种子，并追加一个有效的独立次项目；服务实际停止、重开后仍读取同一临时库，不重新生成正式记录。父任务两组后端全量实际退出零后才开始浏览器验收。外发模型调用不参与验收，来源正文均为合成资料。

实际拖动、版本选择、视角及过程组保存均使用生产 API。浏览器精确比较保存请求、回执、数据库中读取的视图及服务重启前后视图；原节点、边、端口和证据编号集合也精确比较。浏览器的 CSS 坐标显示会舍入，只有 DOM 与原始浮点数之间允许坐标误差小于 `0.005`、缩放误差小于 `0.000005`，持久保存值不放宽比较。恢复后初始化布局不能再次适配并覆盖保存视角。

两位姓名、两个项目、真实 CAS 冲突和图修订冲突均经生产 API 验证。迟到成功、迟到 `401` 及恢复中的迟到研究图页使用真实本地 API 响应，测试传输层明确忽略取消信号以让响应晚到；组件仍保留取消与身份核对。这部分是受控传输验收，不冒充自然网络故障。原文、断言、审核和图修订的完整表摘要在保存前后相同，模型调用数为零。

页面硬刷新后仍按既有界面进入默认项目的问题页；测试主动选择原项目、进入研究图并读取个人视图。个人视图保存不承诺记住全应用导航页签。手机可选择项目、读取和保存；组卡可主动聚焦或缩放，恢复后的原始视角与主动聚焦后的视角分别留图。

实际失败与修正均保留原始日志及截图：

- 首轮单测为 `165 passed`、`20 files`、`1.02s`。首轮构建及类型检查均退出一：恢复请求的修订参数需要字符串，新图夹具遗漏范围元数据。修正后构建 `245 modules`、`1.09s`，类型检查退出零。随后新浏览器文件的未使用参数也曾使类型检查退出一，原日志保留。
- 首轮浏览器命令将原专项文件误写为 `semantic.spec.ts`，只发现十项，实际 `7 passed / 3 failed (1.1m)`。原研究图五项通过；新用例中两项把 CSS 舍入坐标与原浮点数直接相等比较，另一项使用非 ASCII 响应头标记。只修夹具和断言，不改产品。
- 第二轮正确运行原 `semantic-graph.spec.ts` 与新五项，实际 `8 passed / 2 failed (1.0m)`。原语义图五项通过；剩余失败是视角的 CSS 舍入和硬刷新后错误假定仍停留原项目的研究图。修正显示精度断言并主动回到原项目和研究图。
- 一次编排未检查静态命令终态便开始浏览器；发现测试位置类型错误后停止该次运行，实际 `1 passed / 1 interrupted / 3 did not run (19.7s)`、退出 `130`，不作为通过记录。类型修正后，先等待单测、构建和类型检查都实际退出零，再执行最终新五项。
