# 持久队列与持续提取验收

日期：2026-10-10。对应 §2、§4、§7.2/7.6/7.7/7.10、§10/11、§12 M3。基线 b75f62c 工作树干净，开始前核对恢复包的独立还原、206 个跟踪文件与 SHA256。用户提出日常运行零人工干预，本任务补齐自动发现、增量提取与断点接续；人工入口仍供可选纠错。

## 自动处理入口

`rg extract` 省略会话时使用数据库持久队列，可用 `--project` 限定项目；默认单轮最多 20 个会话，`--limit` 为 1–200。`--watch` 将已登记来源扫描、spool 消费、离线 L1 派生和队列提取接在同一循环中，默认间隔 2 秒。项目筛选只限制提取，离线扫描仍处理全库已登记来源。项目归属未知或未允许远程调用的会话，在计数之前跳过；虚拟 rg 人工输入不入队。没有自动登记个人目录、安装钩子或修改客户端设置。

单个 `--session` 保留原入口及报告；批量估算只实测正文 token 与片段数，不生成、不建立队列任务。计数也受外发许可限制。持续模式不能同时指定会话或估算，报告必须指定单个会话；非法额度、间隔和任务数在扫描及服务请求之前拒绝。估算只列首批会话，不是生产队列的增量费用预测。

静态配置、项目、会话和原始元数据快照共同确定任务；审核变化本身不把没有新增内容的会话重新排队。新增原文或配置变化产生新任务；仍沿用原 worker 的审核配置合同，新原文到达时若人工审核已变化，可能重新核对历史候选，不能声称这种情况下只生成新增内容。

## 断点、截止事件与归属

数据库版本 11 新增任务与只追加调度事件。任务输入、截止事件、配置和创建时间不可修改，状态另行更新。任务领取前固定本次最大事件 ID，之后追加的内容留给下一任务，不在旧任务名下消费。遇到已有片段跨越截止事件时等待更完整的任务，不拆已有完成窗口或重复旧候选。

一个数据目录的自动调度器持有系统进程锁；显式会话提取继续使用原会话锁。取得全队列锁才能接管遗留 running，写入取得互斥的恢复依据；不根据锁文件年龄或 running 字段推断进程存活。每次领取生成独立执行者编号，提交必须同时匹配任务、编号及 running 状态，旧执行者不能提交别人的结果。网络期间没有数据库写事务，另一个连接可写入采集信息。

新内容替代尚未执行的旧任务，取消和接续均追加历史。额度不足保留暂停并安排下一个 UTC 日；原文追加和切回旧配置都保留同配置的等待时间。忙碌会话每轮只尝试一次并更新排序，后续会话可继续。失败或人工片段保留缺口，默认不反复重发；`--retry-failed` 是显式重试，在持续模式仅启动首轮生效。

进程在发送后强制终止，未知用量和保守预留仍保留；取得系统锁后接续原任务。响应已完整缓存但候选未提交时，恢复重新验证引用、范围和对象；候选已提交但队列尚未完成时，不重复写入。原话窗口、工作集和正文分量复用同提供方/模型/文本的实测计数缓存，成功缓存恢复不再查询模型窗口；新生成仍实时核验模型预算并实测完整请求，不使用字符数估算。

## 健康与只读前端

`health.extraction_queue` 返回按项目或全库的七种状态计数、总数及分页任务元数据，日期筛选不抹掉历史任务。任务列表不带原文、凭据或执行者身份；错误只存异常类名。done 只代表该次队列任务完成，不等于整个会话全部覆盖，也不等于事实 confirmed。前端与缺口共用健康查询分页，查看不会提取或确认。前端证据见[独立验收](前端持续提取队列验收_20261010.md)。

## 交付边界

此轮补齐运行中的自动链路，未安装系统常驻服务，进程未启动或退出后仍须启动命令。没有把异常强行确认或关闭缺口；关联/问答/MCP 全部自动串接仍待后续实现。元数据与计划仍按会话读取，未做完整 Atlas 规模性能验收。Windows 原生平台、真实客户端、正式参考质量与完整 M0–M4 门槛仍未验收。本任务不把日常零人工目标或完整产品宣布为已完成。
