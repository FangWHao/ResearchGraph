# 物理版本的 MCP 双时间验收

## 范围与实际行为

本任务落实 §2、§7.11 与 §8.2 的只读文件版本查询。原先 MCP 版本入口要求会话原事件，后台物理版本没有该引用，因而无法读取；现在直接使用已保存的不可变文件观察。五个工具及 V: 引用保留，不补造 L0，不新增运行 I/O 或研究对象关联，不调用提取模型。

`research.evidence` 接受一个 `version_id`，详情在 `observations.items` 中，默认 20、最多 100 项，带总数和下一偏移。`known_until` 核对观察与必要快照的入库，`occurred_until` 分别核对捕获快照和实际完整读取时刻。快照及观察入库次序异常时，已知时间采用较晚者；原目录观察入库时间另留 `catalog_recorded_at`。

版本摘要时间和数量仅来自该双截止内的观察。旧的版本表 `observed_at` 不决定后来观察是否可见；晚入库的历史快照不能补入旧已知视图。读取窗口缺失或倒置明确显示未知，缓存保留原读取窗口；发现快照超过截止时不返回其元数据。解析 ISO 时刻后排序，不按字符串或路径接近推定归属。

`research.context` 共用这套规则。指定分析范围时，仍排除没有完整关联范围的文件观察。已绑定原事件的工具报告另按同项目原事件核对，不能借另一个项目的原事件。只返回登记元数据，不打开当前文件或对象正文，不访问网络。

版本 14 的三个追加触发器使新版本、观察和快照改变 `revision`。新增观察即使复用原版本，也拒绝旧 `expected_revision` 的续页。升级已有数据时使旧修订失效，空库仍从零开始；迁移失败原子回滚，原件及不可变观察不变。

## 保留的验收边界

本次查询证明登记记录的可见性与隔离，不重新校验 Git 对象或实际文件，也不证明版本曾用于运行。版本与研究对象及真实运行输入输出仍需直接记录；缺失不会按路径或时间猜补。真实 Atlas 性能、正式参考、真实客户端会话与完整 M0–M4 效果门槛仍未验收，凭据和研究材料继续不进入仓库或模型输入。
