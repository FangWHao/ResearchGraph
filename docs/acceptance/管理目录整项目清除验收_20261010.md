# 管理目录整项目清除验收 · 2026-10-10

## 范围与入口

按用户已确认的“整项目清除”实现当前数据目录中的原件与派生副本。CLI 的 `project clear-preview/clear/clear-status/clear-resume` 与 HTTP 的 `/api/project-clear/preview/execute/status/resume` 共用执行器；本地界面提供预览、明确核对、执行和中断恢复。

本次开发和验证仅使用临时合成项目，不读取真实完整会话、不调用模型、不删除 Atlas 或其他真实资料。外部日志、研究工作区以及用户保存/分享的备份或导出副本沿用既有保留边界，尚未实现按明确外部副本路径清除。不能据此把整个 §11、原生 Windows、大型项目或 M0–M4 标为通过。

## 行为核对

- 清除原事件、原件对象、片段、全文索引、候选与人工记录、模型尝试和输出、队列、版本、编辑、运行、概览、spool、快照及根登记。保留项目仍引用的同字节对象不删除，跨项目行依赖、未登记对象、歧义命名空间和无归属输出在预览阶段阻止执行。
- 主数据库只读预览，不增加业务记录或对象；SQLite 的 WAL/SHM 协调文件可能由只读连接创建，不视作业务资料修改。预览摘要同时核对目标行内容摘要、图修订、对象引用及管理文件身份，执行时在独占锁和写事务下重算。
- 不可变触发器在隐私事务内暂停后恢复；普通入口继续遵循只追加约束。两个全文索引重建、数据库整理、WAL 截断和完整性检查通过后才报告完成。
- 提交前后真实强杀进程、文件删除部分失败均可恢复；恢复期间 Store 与钩子拒绝访问，状态和恢复接口仍可用。相同请求 UUID 和摘要返回同一回执，不重复删除。
- 完成记录不含姓名、正文、会话原标识或工作区原路径。来源摘要阻止同一日志或工作区的自动重导入；后续备份携带屏障。当前恢复元数据上限为 4 MiB，超过时未执行删除。
