# 钩子失败报告界面验收

日期：2026-10-10。基线：`73430d15feec62ff80540e21bcfb3729a8d0a1ee`。本轮沿用户既有前端子 agent 授权，只修改独立面板、健康页接入、测试与本验收文档。父任务负责生产后端、进度、完整回归与发布。

## 行为与语义

健康页增加独立钩子失败报告面板。接口验证选定项目存在，但报告始终属于当前数据目录的全库；切换项目不将报告冒充为该项目独有。已采集的日志行、已记录失败报告、未知日志行、未知异常类别分别展示。副本或轮换中的相同报告分别计数，报告条数不能当成真实失败次数，也不是实际失败次数的准确下界。已读到本次末尾仅表示当前可见日志的采集状态，完整失败历史始终未知。

最近保存的采集状态区分已读到末尾、末行未完整、积压、超限行、缺日志、安全读取受限、读取失败和读取期间变化。时间为最近持久观测或状态变化的入库时间；无变化时不会持续追加状态，不能称每次轮询时间，也不能证明进程存活。当前日志缺失不抹掉已保存的轮换历史。旧 schema 与未观测的统计保持缺失或未知，不补零。

面板只展示脱敏元数据：报告类别、阶段、时间、日志实例、字节位置和摘要。非白名单异常类别仅展示类别 SHA256，不展示原类别字符串；无法识别的原行不显示正文。没有原文按钮，不执行日志中的命令或 HTML，不读取会话、不调用模型。旧健康质量区的指标改名为“已记录钩子失败”，保留接口 null 表示未知的行为。

每页二十项，续页固定首次观测快照，核对偏移、统计和观测身份。读取失败时保留成功页并提示主动重新读取第一页。项目、刷新周期、读取意图和取消信号共同隔离迟到响应；旧项目四〇一不将新项目退出登录。分页或响应错误不能默默少显示，也不能拼成完整失败历史。

## 合成服务与测试区分

独立 `tests/hook_errors_browser.py` 服务仅在临时目录构造两个合成项目与日志，使用真实 `rg.ingest.hook_errors.collect` 和生产 HTTP，不修改既有浏览器库。首次采集二十七行后轮换，第二实例采集两行并留下未完整末行。其中同一报告出现在两个实例，未知正文和非白名单类仅进入脱敏统计。离线烟测得到二十九条报告、二十八条已记录失败报告、一条未知日志行、一条未知异常类别、两个日志实例和快照二；两个项目读取结果完全相同。

独立合成控制器只用于补齐临时末行并追加一条新报告，生产页面与接口没有该写入口。浏览器用它证明旧快照续页不纳入后续报告，主动首读才取得新的采集状态。测试中的旧 schema、未观测、旧接口四〇四和错误分页元数据是明确模拟。迟到测试延迟已从真实 API 取得的旧快照或错误令牌响应，并受控忽略传输层 AbortSignal，以核对页面自身的取消／身份检查；生产取消逻辑不改。
