# 原生补丁与单侧候选全文验收

日期：2026-10-10。基线提交：`9e83e953ec7887e08aeb6c687b07c9b52c6c8770`。本轮对应规格 §2、§6.3/6.4/6.5/6.6、§8.3、§9.5、§15 的部分协议与证据显示要求；不是正式 M2 全量验收。

## 行为与证据

Codex 原生 `patch_apply_begin` 保存为执行元数据，`patch_apply_end` 保存为工具结果。只关联同实际会话、同调用 ID 的唯一记录，优先已有原始补丁请求；否则使用原生开始，不把外层执行器命令解释成补丁请求。缺少请求和开始时等待，后来同调用开始可继续派生；重复 ID 明确歧义，不按相近时间、顺序或命令选取。

按固定修订的[官方协议定义](https://github.com/openai/codex/blob/806d9732c974bc8a51b8317c1bd8985544fe627c/codex-rs/protocol/src/protocol.rs)及[兼容事件转换](https://github.com/openai/codex/blob/806d9732c974bc8a51b8317c1bd8985544fe627c/codex-rs/protocol/src/legacy_events.rs)，现代回执核对 success/status、开始与结束变更、回合、原请求文件/操作/新增正文/移动目标；结构化回执允许 stdout 为空。旧回执缺少变更时同时要求成功字段和严格路径/操作摘要。普通函数输出中的同名 JSON 字段不能冒充原生元数据。未知操作或格式保留 L0，让派生失败；矛盾保留报告，不生成完整版本。

一致的删除前全文可以保存，即使结束报告失败；新增后的全文只在成功且一致时保存。更新与移动仍是补丁或结构化报告，不补造完整前后文本。没有原始补丁请求时明确注明 `native_patch_input_missing`；这与缺少原生开始的等待状态不同。版本沿用 `agent_edit/tool_reported_utf8/direct_record/candidate`，没有物理读取证明或研究确认；原生补丁结束也不覆盖外层执行器的退出状态。

证据 API 用 `reported_before`、`reported_after` 返回对应单侧全文，`complete_versions=false`，另一侧未知。空文本是已报告的空文本，缺失 after 不是空文件。原有双侧差异与 `patch_only` 保留；有单侧身份却不能展示时，不再抹掉已知侧。每项最多 64000 UTF-8 字节、2000 行，整事件正文合计最多 64000 字节；超限不返回部分全文。源文件消失后仍从已保存对象读取，不从当前文件或 Git 修复历史。

迟到重复开始不会修改不可变编辑或版本。当前证据页与文件图标明关联歧义；固定较早已知截止的文件图仍使用当时可见记录。原始补丁请求与唯一原生开始同时存在，不因两种来源本身误标歧义。
