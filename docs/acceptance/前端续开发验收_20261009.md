## 真实统计与含义

页面直接读取 `/api/health?project=...`，不从其他计数推导正常或成功总数。

| 统计项 | 合成主项目实测 | 口径 |
| --- | ---: | --- |
| 已注册采集来源 | 2 | 全库 |
| 已知来源路径 | 2 | 全库 |
| 原件回执 | 3 | 全库；原件与任务、事件分别计数 |
| 未完成采集任务 | 2 | 全库；queued 和 running 各一条账本记录 |
| 采集失败任务 | 1 | 全库 |
| 快照记录 | 4 | 当前项目的记录数，不表示四份成功快照 |
| 跳过标记 | 1 | 当前项目 |
| 异步采集标记 | 2 | 当前项目；请求时点与采集时点可能不同 |
| 文件遗漏标记 | 2 | 当前项目；部分文件未被包含 |
| 元数据未知 | 1 | 当前项目；旧记录缺少完整元数据 |
| 钩子失败 | 未知 | 后端尚未建立完整失败账本 |

合成快照中存在同一行同时带跳过、异步与文件遗漏标记的情况。这些计数无法相加为异常总数，无法从四条记录中相减求成功数。异步标记不证明发生竞态错误，running 账本记录不证明进程仍活跃。

浏览器切换至“合成空项目”后，快照记录、跳过标记为 1，其余三个标记为真实的 0；切换至“验收批量项目”后，五个快照计数均为 0。两次切换中全库回执数始终为 3。旧接口缺少 `ingest` 或 `snapshots` 时，对应项显示“统计缺失”，其他原始事件、游标和覆盖统计仍可查看。

阶段观测以当前项目和接口 UTC 日显示，真实合成账本在 HTTP 与表格中一致：

| 阶段 | 尝试 / 已发送 | 平均输入预算占比 | 有计数的样本 | 校验样本 | 校验拒绝 | 引用失败 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| pass1 | 1 / 0 | 未知 | 0 | 0 | 0 | 0 |
| pass2 | 1 / 1 | 0% | 1 | 1 | 1 | 1 |

这两行由父任务直接创建合成账本，没有发出模型请求。未知占比不会补为 0%，真实 0% 保持可见；校验拒绝包含引用失败，不能相加。无阶段记录时页面明确说明：当日无观测无法证明历史提取完整。

## 浏览器交互验收

新增四个 Chromium 用例分别验证：

1. 用授权 HTTP 请求取得实际健康对象，与每个页面计数逐项核对；核对上述阶段统计；切换三个项目，分别验证全库与项目统计；390 像素宽度无整页横向溢出，阶段表可聚焦并通过方向键实际横向滚动。
2. 兼容旧接口：先取得真实健康响应，再移除新增对象模拟旧版本。十项统计显示缺失，其他真实数据仍呈现。此用例不是实测统计数的替代证据。
3. 健康请求返回 503 后停止加载并显示局部告警，重试重新走真实 HTTP 服务，恢复统计后旧失败文案和告警消失。
4. 健康请求返回 401 时回到统一鉴权入口，不能继续展示健康记录。

原有四项浏览器回归同时通过，涵盖同源鉴权和令牌清除、问题与时间线、证据定位、研究图引用、跨页整片段复核、版本冲突刷新、人工修改及搜索。503 和 401 的用例采用明确的浏览器响应故障注入，恢复时使用真实服务；实测健康计数用例没有替换 HTTP 统计内容。

## 取舍与下一步

统计采用接口原始口径，保留未知，避免派生出接口未提供的成功率、实时进程状态或“全部健康”结论。将可重试的健康读失败保存在局部状态，401 交给现有鉴权逻辑；放弃通过全局消息展示所有读取失败，因为局部重试成功后旧全局错误会残留。

本轮没有实现或声称实现完整钩子失败账本、实时进程探测、快照逐条审查或真实 Atlas 质量验收。静态资源仍按现有方式单独构建，Python wheel 不自动包含 `web/dist`；使用源码检出加 `pnpm build` 后启动本地服务，安装 wheel 时需通过 `--web-dir` 指向独立构建目录。
