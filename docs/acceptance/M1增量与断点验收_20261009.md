# M1 增量与断点验收 · 2026-10-09

本轮落实 §2、§7.2–§7.10 的增量所有权、覆盖完整性与重试恢复。前端已经按用户授权提前完成基础工作区；本轮不读取真实会话、不发送模型请求、不代替 Atlas 人工效果验收。

## 修复的行为

原实现处理一个用户决定后，再追加同回合的助手回复，重新组合的片段身份变化，导致旧决定再次生成 candidate。起始合成回归为 1 failed、1 passed，确实复现重复，而非仅修改缓存命中次数。

版本 5 持久保存配置下的片段窗口、原始上下文与状态。追加仅规划新事件；晚到工具结果携带原调用为 context_only。排除与镜像按原因关闭覆盖，不参与真实回合边界。恢复跳过已完成子片段，按事件顺序和字节位置处理剩余窗口；旧配置的 pending 不阻止新预算配置完成。

候选和无候选结果与计划完成标记同事务提交，覆盖视图可在服务离线时恢复。多个窗口中任一 pending 都保留事件缺口；至少一个 covered 且没有 pending 时，最后一个无候选窗口不能把整事件标成无候选。处理中导入的新事件属于下一快照，保留 pending，不能把当前会话标为全部处理。

人工失败默认不重新调用模型；显式 extract --retry-failed 才重试当前配置。同配置同片段更新原队列记录，成功后关闭通知，历史尝试保留。配置、范围或人工审核变化继续遵循重新核对合同，模型原行仍是 candidate，已有人工确认不覆盖。

旧库升级事务原子。缺少旧片段计划时，只继承精确旧缓存键、完整原文前缀的三阶段覆盖及项目尝试证明；项目变更、配置不符或证明不足均不猜旧所有权。会话元数据和计划清单仍整批读取，尚未做大库性能验收。
