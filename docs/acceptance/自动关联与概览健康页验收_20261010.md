# 自动关联与概览健康页验收

日期：2026-10-10。范围：规格 §2、§9 的阶段队列健康展示，由用户已授权的前端子 agent 完成；后端流水线由主 agent 开发。本记录验证界面和实际本地 HTTP 接口，不替代真实模型、真实客户端或 M1–M4 的正式门槛。

## 改动与边界

- 新增独立的“自动关联与概览”区域，读取 `health.pipeline_queue`。总数与七种状态计数来自接口的全部范围；不使用当前页任务推算数量，也不与提取队列相加。
- 明确显示跨会话关联或概览、项目 ID、整个项目或会话目标、尝试次数、时间、等待原因和错误。目标标识与会话编号矛盾时显示“目标字段不一致”，缺失时保持未知。
- 暂停显示等待重试。日额度、提供方计数不可用、执行器暂不可用和阶段忙碌分别解释，展示实际下次尝试时间；时间记录不证明任务已经执行。
- `pipeline_offset` 默认 0，独立于提取与覆盖缺口的共享 `offset`。翻页保留另一个队列的位置，切换项目分别重置为 0。
- 健康响应按项目、两个分页位置、刷新代次与重试代次匹配；中止请求并检查当前请求身份。项目变化时不展示旧统计，即使旧请求无法中止、后来完成，也不能覆盖新项目或触发过时鉴权错误。
- 缺少整个对象、数量、任务字段或分页信息时显示未知。真实零值仍为零。阶段结果以纯文本折叠展示，仅作诊断；概览不作为证据，任务完成不代替事实确认。

生产前端改动：`web/src/HealthView.tsx`、`PipelineQueuePanel.tsx`、`health.ts`、`health.css`、`types.ts`。测试改动：`web/tests/health.test.ts`、`web/tests/browser/pipeline-queue.spec.ts`、`tests/frontend_server.py`。主 agent 统一更新进度、决定及 PR，本子任务未修改这些根文档。

2. 阶段分页从 0 到 50 时，提取与覆盖仍在 0；再翻提取到 50，阶段仍在 50；返回阶段首屏，提取仍在 50。界面没有发送写入请求，图版本与记录审核状态保持一致。

4. 特意让浏览器忽略健康请求的中止信号，先返回新项目的 2 项，再让旧项目的 54 项回包被实际解析；等待浏览器渲染后，新项目仍显示 2 项，提取仍显示该项目 1 项。
