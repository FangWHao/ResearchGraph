# 完整 L2 语义图验收

本轮落实执行版 §2、§5、§9、§10、§15 A 及原设计 v1 §7 的语义图和折叠条件。开始前已检查进度末尾、相关章节和开发决定，核对 `a6cc282` 基线恢复包，300 个跟踪文件独立恢复后字节一致。全部材料为合成记录；未读取完整真实会话、外发研究原话或调用模型。

## 行为与证据

- 新增 `rg/query/graph.py`：全部 L2 断言共用一个 Reader 与 SQLite 读快照，保留双时间、历史审核、内容版本、更正、范围、依据及所有证据引用页；不使用画面 2000 条投影计算语义。
- 节点以对象身份与完整范围的规范摘要标识。端点只有同项目、同范围的可见内容版本才解析，缺失不回退；所有版本保留，多个有效版本无默认“当前内容”。人工合并单独保存，不改变对象身份或审核状态。
- 关系可有环；端口、原方向和证据保持。合法方向按 §5 与现有校验器约束标记；历史异常仍保留但不冒充合法。三种汇合分别保留共同必需、比较被选/未选和证据综合的结构；重复命名端口、错误选中对象或非汇合目标标记无效。综合不证明统计独立。
- `graph` CLI 与 `/api/semantic-graph` 分页提供节点、关系、汇合、合并、状态事件和未解析端点。每页 1–100 项，续读固定双截止和修订；变化返回 409。HTTP 沿用令牌、Host 与同源检查，拒绝重复范围字段和未知参数。只读库、不读取原话对象或当前工作区、不重建缓存。
- 历史 ZIP 的 `graph.json.semantic` 复用同一引擎和双截止；稳定节点摘要不携带临床范围明文，分享副本继续用原导出的遮盖规则，不改原记录。
- 前端子 agent 修复版本显示与折叠保留。原始成员、重要状态历史、其它范围、候选审核、内部和所有边界关系均可定位；不同角色的比较端口不合并为使用。同修订展开恢复原 ID 和位置。专项采用独立虚拟合成来源，避免增加真实日志路径统计。

## 验收范围

固定案例覆盖：循环、同身份多版本/多范围、更正的双时间、采用与证据独立、三种汇合、多条汇合、非法端口、同范围缺失、跨项目拒绝借用、未知范围、晚到证据、未知记录时间、2005 个内容版本、105 个证据引用、104 条跨页关系、仅检索主题、人工合并、错误查询与修订冲突、禁止网络及原文访问、实际 CLI/HTTP、导出与查询同源及遮盖后的标识完整性。

首次专项失败来自测试把空范围对象当作合法未知范围、误用 HTTP 构造参数、遗漏合成静态页；已按现有 Reader 合同修正测试。前端首轮暴露选择与布局相互重建、种子被统计为物理 Claude 日志，分别修复状态同步与虚拟来源类型；验收采用最终重跑结果。全量固定案例另发现应用生成 UUID 的数字尾段被误判为手机号：结构 UUID 单独识别，研究文字继续遮盖，自定义规则若明确涉及应用 UUID 则拒绝发布；临床字段不借用该例外。

## 尚未验收

`semantic_graph_complete=true` 仅说明完整读取指定条件下的 L2 集合，`l1_dependencies_complete=false` 仍明确返回；不证明实际运行 I/O 完整、科学结论或领域审核正确。节点内部版本和引用没有静默截断，完整构图仍按项目加载元数据，真实大型项目的内存与时延尚未测量。

未选比较输入的影响传播合同已向用户提问，尚未收到选择；本轮没有猜测传播、写提醒或改变正式采用状态。项目级临床配置、隐私清除、完整 §15 A/B/D、Atlas 正式参考和 M0–M4 的真实质量门槛继续待验收。
