# 自动工作树发现验收

日期：2026-10-11。依据执行版§2／6.6和明确项目归属原则，沿用户自主开发授权实现一次开启后的持续发现。仅用公开合成Git与临时数据库；不读取真实会话正文、不删除真实项目、不安装日常钩子、不调用远程模型。

## 交付行为

- 默认关闭；新项目可一次使用 --follow-worktrees，已有项目可通过带修订的CLI或本机认证HTTP开启。生产scan／watch每轮执行已开启的批次；暂停保留已登记根与历史，不要求逐个确认新成员。
- 共同Git目录必须在本机唯一对应一个项目；逐成员核对当前绝对目录和Git身份，保留登记时元数据。跨项目同共同目录、相交路径、身份变更和清除屏障不会新登记；提交前重核期间新增的交叉根和策略变更。不按远端摘要或cwd合并项目，不重新归属会话或跨项目片段。
- 完整NUL工作树清单有1MiB／512成员上限，非法或截断整份作废，只保存摘要；固定Git调用隔离环境、禁用钩子／监控器／远端，不执行目录文字。每锚点共享2秒，默认每轮4锚点／16成员；数字锚点轮转和成员摘要游标持久保存，HEAD变化不重置成员进度。
- 新根登记与快照清单发布分开；中断后下一轮重核发布。相同项目嵌套根选择最长已登记路径，不消除跨项目歧义。诊断是最近一次成员页的计数，list_complete只说明读至当前清单末页，不证明全部路径可用、会话完整或真实运行I/O。
- 迁移29保留L0和项目历史，策略／观测只追加；四张归属表进入整项目清除。全局游标仅保留受约束的静态键和非负数字，没有正文／项目身份。只读列表由数据库快照分页，续页带修订，不探测Git、不写库；策略写入口严格字段、类型、修订、令牌与同源。
