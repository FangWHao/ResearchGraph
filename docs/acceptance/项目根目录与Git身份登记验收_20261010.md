日期：2026-10-10。起始提交：`ecbac1d1e12e018e9816495b3f1e0302f5e7bd9c`。范围为执行版 §2、§6.6、§10、§11、§15 B，以及原设计书第 5 节的项目登记规则。整项目清除沿用用户已选择的粒度；本轮只清除临时合成项目。

## 行为

已有项目可通过 `project root-add` 追加本机仓库、独立 worktree、数据目录或路径别名。`project add --alias` 将别名保存为 alias 类型。默认 auto 保留旧入口对非 Git 工作区的快照授权；已识别的独立 worktree 保存为 worktree。显式 data 只登记目录，不探测 Git，也不加入工作区快照清单；显式 worktree 必须取得与共同目录不同的独立 Git 目录。

```bash
uv run rg --data-dir /tmp/rg-demo project root-add \
  --project PROJECT_ID --path /workspace/another-worktree --kind worktree
uv run rg --data-dir /tmp/rg-demo project root-add \
  --project PROJECT_ID --path /data/research --kind data
uv run rg --data-dir /tmp/rg-demo project roots --project PROJECT_ID --limit 100
```

新登记保存本机规范路径、根目录 ID、类型、Git 工作树、独立 Git 目录、共同目录及远端 URL 的 SHA256。Git 路径使用 [官方 rev-parse 接口](https://git-scm.com/docs/git-rev-parse)。远端摘要只取 `git config --local --no-includes` 的配置内容，不应用 URL 改写，不连接远端；原始 URL、其中的用户名、口令及参数均不写入数据库或命令结果。摘要代表精确配置字节，不是跨传输协议、跨克隆或凭据变化后的统一仓库身份。

Git 读取沿用隔离环境与固定命令参数，禁止网络、仓库钩子和文件监控器，整体预算 2 秒。缺目录、Git 未识别、探测失败或超限分别保存缺失或不可用状态，不以部分元数据证明 worktree。元数据只反映登记时的观察，不保证之后的路径仍对应同一仓库。

相同本机路径重复登记返回原根目录 ID、元数据及修订；类型或项目不同则拒绝覆盖。共同目录或远端摘要相同不合并项目，也不改写会话归属。登记新根目录推进图修订，使旧分页可拒绝继续；`project roots` 使用同一只读数据库快照分页，并支持 `--expected-revision`。它不探测当前文件，不调用模型；数据库不存在时拒绝，不创建空目录。

版本 18 只为 source_roots 增加 git_metadata 字段。旧登记保留原字段，新元数据为未记录；升级不扫描旧根目录或补造身份。迁移失败整体回滚，恢复后可重复升级，L0 原件保留。CLI 登记更新钩子使用的根清单，重试可重建该派生清单；它不安装钩子。重叠路径继续遵守已有“归属歧义拒绝选择”规则。

## 边界

只登记明确指定的本机根目录，不自动遍历 Git worktree 清单、不猜同远端项目、不映射其它机器路径。跨项目会话的片段归属、跨根文件身份和实际运行 I/O、真实客户端与性能、Atlas 正式人工参考及完整 M0–M4 仍待验收。旧登记元数据不会因再次 root-add 而刷新；当前命令不提供移动、删除或覆盖登记。
