# 原生客户端 MCP 与注入排除

本轮覆盖执行版 §2、§6.3、§6.5、§7.11，以及生成接入包的实际只读调用。已有 SDK 验收不能证明原生客户端能注册和调用全部工具，因此补充本机 Codex CLI 0.162.0 与 Claude Code 2.1.280 的隔离验收。

## 修复与历史边界

实际 Codex 日志将工具命名空间与叶名称分开保存，Claude 使用下划线替换的完整名称。旧规则遗漏这两种 ResearchGraph 名称，Codex 工具返回包装的元数据也可能留在瘦身结果中。解析器现在保留命名空间，并明确识别本服务生成的五个别名；其他 MCP 服务及相近名称保持各自身份，不误作本机编辑或 ResearchGraph 注入。无法识别的命名空间结构保存原文并计数，不静默丢弃。

解析账本版本升为 3，瘦身版本升为 4。瘦身在接受缓存之前重新解析保存的受影响工具原件，必要时核对同会话唯一调用；删除旧的错误派生缓存并记录排除覆盖，不改写原始事件行。引用校验也检查保存原件。Worker 静态配置包含这两个版本，旧的待执行片段不能通过恢复缓存重新发送；旧计划和已有科研记录仍保留。

本轮没有批量撤回已经发布的旧模型断言，也没有补改过去的 L0 分类或解析账本。旧已发布记录的污染审计仍待落实；本轮保证新扫描、重新瘦身、当前引用校验和新配置下的处理不会直接接受这些工具原件。

Claude 首次扩展验收只有四个工具可用，证据工具实际返回工具不存在，客户端仍退出 0。触发原因是该工具的根级 `oneOf` schema；[Claude 官方 MCP 文档](https://code.claude.com/docs/en/mcp#tool-input-schemas-with-a-root-level-combinator)说明这类转换受客户端能力和配置影响。现在发现列表提供普通对象 schema，并说明五种引用只能选择一种；服务端仍使用原完整互斥 schema 校验，没有放宽执行端参数检查。

## 实际原生验收

`scripts/check_native_clients.py` 为两种客户端创建独立配置目录、公开合成 Git 工作区和数据库，从产品生成的配置启动真实 stdio 服务。回环 HTTP 固定响应依次请求 context、node、history、search、evidence，最后回复完成标记。脚本检查每个实际工具返回、标记、错误状态、数据库完整逻辑转储和 Git index，不把进程退出 0 单独视为成功。

已运行命令：

```text
uv run python scripts/check_native_clients.py
Codex CLI 0.162.0：五个工具全部通过，六次固定响应请求，实际退出 0
Claude Code 2.1.280：五个工具全部通过，六次固定响应请求，实际退出 0
两种客户端：数据库逻辑转储不变，Git index 不变
```

这不是远程模型实测。固定响应的用量字段只是协议占位值，不作为真实 token、质量或成本证据；没有使用目录中的密钥，没有读取完整真实会话，没有安装日常钩子。原生测试日志包含客户端自带提示，只留隔离目录，不进入 fixture 或仓库。固定案例只保留必要原生字段并脱敏，见[样本说明](../../fixtures/transcripts/原生客户端MCP样本说明.md)。

## 收尾钩子与剩余验收

原生短会话的原配置对照中，Stop 异步调用未稳定写入 spool；仅在隔离测试副本里改为同步后，两种客户端均观察到 Stop。Codex 的 [官方钩子文档](https://learn.chatgpt.com/docs/hooks)也说明会话结束会取消未完成异步钩子。生成配置仍沿既有 §6.8 规则，Stop／SessionEnd 是否改同步的问题已发给用户，答复前不修改产品配置。

尚未证明完整客户端钩子调用链的 p95、所有客户端版本、实际 Atlas 提取质量、完整运行输入输出、M2 全量采集或 M3 两周使用。原生 MCP 通过不代替上述门槛，整体 M0–M4 仍未完成。完整测试与隔离安装结果见下文。
