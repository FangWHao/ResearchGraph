# M2 快照与钩子验收 · 2026-10-09

本任务落实 §2、§6.8、§8.2、§11 的钩子入口、影子快照和备份，保留 §14.8 的开发会话禁用规则。没有改写执行规格、启用个人钩子、读取完整真实会话或调用远程模型。完整 M2 与真实 M1 效果门槛仍未通过。

## 实现与证据

- `rg-hook` 原始字节先 fsync 和原子改名；异常静默返回 0。4 MiB 以上输入有界流式保存原件，不解析，消费显示 held。日志只保存时间、阶段和异常类，不注入上下文。
- 明确根目录清单来自 CLI，钩子不使用 SQLite。异步子进程执行隔离 Python 下的本软件绝对入口；实际恶意同名模块用例没有执行项目代码。`init` 与 `hook-config` 只生成示例，Codex 信任和个人设置没有改动。
- 自有裸仓库与 index 保留原始字节、权限和链接目标；忽略 `.gitignore`、`.rgignore`，拒绝父目录链接替换。单文件大于 5,000,000 字节与嵌套仓库只登记遗漏；dirty 无法安全测定时记未知，不重新读取遗漏的大文件。
- 超时、忙、目录或文件变化没有有效提交；自包含提交不根据时间推断父子。快照记录独立排队，原提示先被消费不影响快照；版本 7 的追加约束和唯一标识防止恢复重复。消费者检查提交引用的全部树和 blob，原工作区已删除也可入库。
- `health.snapshots` 区分 skipped、partial、async_race 和旧元数据缺失。错误日志不是完整失败账本，未接入客户端的实际故障数仍未知。
- 备份仍使用 SQLite backup API；捕获、消费和复制共用影子仓库锁，复制队列链接而不读其目标，核对备份自身的提交引用后才写成功清单。

协议核对来自 [Codex 官方钩子文档](https://learn.chatgpt.com/docs/hooks)、[Claude Code 官方钩子文档](https://code.claude.com/docs/en/hooks)。原始字节与只读元数据操作参考 [Git hash-object](https://git-scm.com/docs/git-hash-object/2.43.0.html)、[Git status](https://git-scm.com/docs/git-status)和 [Git rev-list](https://git-scm.com/docs/git-rev-list)。Codex 的 SessionEnd 按客户端同步执行，即使示例设置 async，入口也仅快速保存原件。

## 保留的边界

大文件后台摘要、运行/编辑/产物映射、跨 worktree 自动会话归属、真实客户端安装与完整失败账本仍需开发。客户端强制杀掉入口时，原件或日志不能证明每次快照都已登记；没有把这项缺口隐藏为零。Linux/WSL 合成验收不替代 Windows 原生平台测试、本机全部会话双导入与真实 kill -9 恢复。Atlas 正式人工参考和质量门槛仍待核对，完整 M0–M4 目标保持进行中。
