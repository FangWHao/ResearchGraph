# 移动端项目切换验收

日期：2026-10-10。起始提交：`ecbac1d1e12e018e9816495b3f1e0302f5e7bd9c`。本轮只修复手机布局及增加独立浏览器验收，后端项目根目录登记和主文档由父任务维护。

## 问题与修复

原 `styles.css` 在宽度不超过 760 像素时隐藏整个 `.project-picker`，因此 390 宽页面无法从全局入口选择项目。此前精确状态验收通过桌面选择后缩窄检查，并未证明手机入口可用。

本次将现有项目控件在手机主内容顶部固定显示，保留原来的单一 `select`、完整项目名称和 `onChange`。控件高度为 44 像素，字号 16 像素；页面上方预留 88 像素，侧边导航仍沿用现有布局。手机隐藏该控件下方的会话／记录数量以留出选择空间，桌面规则不改。没有新增另一份项目状态、重复选择器或请求逻辑。

项目切换仍使用已有隔离合同：关闭旧详情，重新读取所选项目；各项目页面内草稿独立，旧项目迟到响应不能覆盖当前项目。此布局修复不改变记录审核、采用、证据或运行状态，不写入项目资料。

## 真实浏览器核对

新增 `web/tests/browser/mobile-project.spec.ts` 三项，使用原合成服务及生产本机 API。页面从打开时就是 390×844，直接操作手机项目控件，没有先用桌面选择再缩窄的步骤。控件验收包括屏内位置、至少 44 像素高度、中心点未被遮挡及页面无横向溢出。

1. 从“合成研究 · 界面信号验证”打开记录及原文，关闭抽屉后直接切到“合成空项目”，核对空项目没有旧问题或详情，再切回核对原记录。实际项目图在操作前后完全相同，浏览器没有 API 写请求；随后在 1440×1000 核对桌面入口仍可见。
2. 在“验收新增人工记录项目”和“验收新增人工记录项目二”分别输入尚未提交的草稿，直接往返切项目。每个表单只恢复自己的正文和归属，项目图未变，也没有自动提交。
3. 使用真实 `/api/versions` 响应，故意去掉页面等待的中止信号并延迟第一项目的回包；在 390 宽先切到“验收批量项目”，待旧回包确实被解析后核对当前版本 ID 集合、项目选择与鉴权仍属于新页面。这里仅模拟响应到达时序，响应数据和服务查询均来自真实后端，没有伪造版本。

原有 110 项没有删改，本轮增加三项。完整浏览器回归由父任务在后端验证结束后串行接续，本文不预报其结果。专项没有失败，未增加超时或重试。首次三项通过后只调整截图滚动位置，最终重新运行该三项并保留两次日志。
