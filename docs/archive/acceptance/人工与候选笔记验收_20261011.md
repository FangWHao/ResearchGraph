# 人工与候选笔记验收

日期：2026-10-11。范围：执行版 §2、5.4、8.1、10；基线为 `48d046200f9611d3eef93d697cb08454e1e94587`。本批使用公开合成资料和临时数据库，不读取完整真实会话，不调用远程模型。

## 可使用的行为

`rg note`、本机令牌 HTTP 和两类客户端的显式笔记技能保存人工原话，直接登记 manual／human／confirmed。MCP 新增 `research.propose_note`：固定启动项目和 model:mcp／model_inference／candidate，不允许调用方覆盖项目、身份、依据或审核状态。五个查询工具保持只读；候选请求才打开写连接。人工确认只追加审核动作，最初的模型记录仍是 candidate。

笔记是独立的 `note` 对象，沿统一 claims、证据窗口和复核界面保存。完整空白、换行与字面 HTML 保留；发生时间与登记时间分开。`about` 只能为空或同项目对象 ID，人工修改不能重定向；笔记范围可以为空，不继承关联对象的范围。关联只用于查找，不创建影响传播关系，笔记不具有科研采用／证据／运行轴。

请求 UUID、原件、claim 和回执在同一事务追加。完全相同的重试先返回已有回执，再考虑旧修订；改变意图或跨操作复用 UUID 返回冲突。重放反映当前有效审核状态，不会复活旧候选。迁移28保留原件、历史、索引、触发器和外键关系，失败回滚并恢复外键开关。笔记回执进入整项目清除选择，公开案例核对其他项目及共享字节保留。

直接记录的笔记不再自动提取。模型笔记自身原话不成为科学证据；笔记排除自动工作集、关联、独立原话对象匹配、概览和采用目标。原生 MCP 提议调用及结果排除回流，解析版本更新为4。人工笔记可进入查询状态卡，所有笔记可被检索并按对象和历史查证。科学提取 schema 仍限制原有六类对象。

前端提供独立研究笔记页，服务端先按类型／审核状态过滤再分页，50条后可继续加载。人工表单保留每项目的当前草稿和请求 UUID；忙时不重复提交，丢失回包可安全重试，旧请求迟到200不能清空新草稿。候选可以沿统一入口确认、驳回或修改，编辑保留原版本和不可变关联。
