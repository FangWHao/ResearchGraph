# 科研依赖的只读预检验收

本批把已有科研连接变成可核对的清单，为后续实际迁移提供范围依据。已有科研依赖的正式重归属仍受保护；预检没有改变原件、确认历史、科研解释、原生事实或分区。

## 当前接口

健康页的物理片段面板增加“只读预检科研依赖”。先选择完整首末记录与目标项目，再按原归属请求检查；有科研依赖时展示数量和片段外必需原件，不自动扩大范围或迁移。改变目标、范围或身份后旧清单失效；409要求重新读取，晚到响应不能覆盖新意图或错误关闭新身份的面板。

本机HTTP为 `POST /api/project-fragments/dependencies`，沿现有令牌、同源及严格JSON合同，只读打开数据库。请求沿正式归属字段，可另带 `limit`（1至100）、`offset` 和 `expected_plan_sha256`；续页必须带首轮依赖摘要。CLI为：

```bash
uv run rg project fragment-plan --request-file 请求.json
```

`complete`表示已声明外键与结构化引用展开完整；`closure_closed`表示没有片段外必需原件。`assignment_available`只描述当前直接归属保护，`migration_applied`始终为false。预检不占用请求UUID；无依赖时同一UUID随后可正式保存。有依赖时仍需后续完整迁移，不能修改已确认记录来绕过保护。

## 固定案例

- 证据、同对象全部版本、替换和人工审核、关系端点一起保留；原已确认／新候选四轴与整库不变。
- 模型输入、工作集、重叠上下文及待处理片段计划；片段外必需原件按完整记录报告，不按正文块拆开。
- 原生运行请求／结果、编辑、文件版本、I/O及保存来源资格的关联调用；未声明外键的连接仍核对。
- 图修订不变而模型日志状态变化时，旧依赖摘要409；冻结续页不混合不同清单。
- 坏JSON、错误类型、超SQLite整数范围、缺失引用、未知表／列与各执行预算耗尽显式不能完整核对。
- 只读数据库、原件及Git读取禁止探针；CLI与鉴权HTTP、重复字段拒绝、UUID不占用和同意图正式保存。
