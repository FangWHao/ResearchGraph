# 项目钩子接入验收 · 2026-10-13

本轮增加已登记项目的本地钩子安装，界面保持三个默认入口。安装和真实生效分别报告；没有安装到个人 试点项目 配置或 ResearchGraph 开发会话，没有开启个人持久信任或常驻服务。

## 接入范围

`hook-install --project PROJECT_ID --root WORKSPACE --client claude|codex` 检查项目、本机根目录及唯一归属。Claude 合并 `.claude/settings.local.json`，WSL／Linux Codex 合并 `.codex/hooks.json`；`--check` 不写客户端文件。原字段和其它事件／处理器保留，第一次新增八类事件，重复调用不重写字节。JSON 格式可能重排，字段值不丢失；不另存包含用户设置的完整副本。

损坏／重复 JSON 字段、非普通文件、超过 1 MiB、配置路径链接、已有同名定义被修改或重复、检测到发布前并发编辑时拒绝覆盖。数据目录内进程锁串行化本工具安装，原子发布完整 JSON；外部编辑器不参与锁，最后一次核对与原子替换之间仍存在短窗口，不宣称跨程序事务。文件创建使用私有临时文件。

执行命令固定本次 Python 环境及本包入口，保留 venv 路径、不依赖 `rg-hook` 的 PATH。Claude 使用执行文件和参数数组，Codex 使用本机 POSIX 引号；原生 Windows Codex 尚未验证命令 shell，安装前明确拒绝，WSL 可用。隔离启动不导入工作区同名模块，入口导入／运行异常也静默退出 0。

项目本地定义可能由子目录继承，明确位于范围外或最近唯一登记根属于其它项目的事件不采集。无法解析或超大输入仍保留原件，由队列处理未知／超限，不能把未知归属冒充排除成功。此筛选只约束本钩子采集范围，不回填会话归属或科研状态。

`configured` 表示配置存在，`activation=unknown` 不证明客户端执行。Codex 重开项目后仍需原生 `/hooks` 审查及信任；功能禁用、工作区未信任或管理策略可能影响执行。命令不修改个人设置、信任数据库或其它项目。

## 原生测试和红灯

执行 `uv run python scripts/check_native_hooks.py`，固定回环响应、公开合成资料、独立 HOME 和客户端配置。Codex 0.162.0 使用仅此隔离调用的原生已审查定义执行选项，不写个人持久信任；Claude 2.1.280 使用独立非交互工作区。远程模型调用为 0，协议中的用量字段是固定占位，不能作为模型成本数据。

原版异步 Stop 的 Codex 实测失败：实际收到了开始、提示和结束事件，缺少 Stop，命令退出 1、包装 18.123 秒。不是夹具伪造。更早一次脚本误将 Store 当上下文管理器而退出 1，已修正；后续一次 Claude 空 MCP 配置不合法退出 1，已使用明确空服务表修正。所有失败日志和隔离目录保留。

Stop／SessionEnd 调整为两秒预算的同步回执，仅写 spool；不读会话、不联网、不调模型，后台消费方式不变。规格 §6.8、示例和安装定义一致更新。修正后两个真实客户端实际退出 0，各发送一次回环请求，并实际保存以下四类事件：

```text
SessionStart  UserPromptSubmit  Stop  SessionEnd
Codex 0.162.0：四类齐全，Git index 未改，数据库未改
Claude 2.1.280：四类齐全，Git index 未改，数据库未改
整体脚本：退出 0，包装 15.181 秒
```

另用实际提供的 rg 控制台入口执行五次 CLI：初始化、登记、检查、安装、重复，均退出 0；检查不创建客户端目录，首次八类事件，重复字节一致，生效仍为未知。第一次验收误用不存在的 python -m rg 入口而退出 1，已纠正，未改变产品入口。两个原生合成项目各存在一个提示快照回执；该计数不代替快照完整性或 p95 验收。

这不是个人钩子已经启用的回执，也不是全八类事件、全部客户端版本、整条快照 p95、kill -9 或真实科研采集的验收。
