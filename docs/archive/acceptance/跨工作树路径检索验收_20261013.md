# 跨工作树路径检索验收

日期：2026-10-13。按用户自主开发、保持简单桌面界面和减少重复测试的授权推进§2／6.6／7.6–7.8；本批未改变前端，没有读取个人完整会话或科研文件，也没有调用远程模型。

## 实现结果

- `rg/extract/path_context.py` 读取当前项目已登记的本机根和保存的逐记录目录声明。主工作树与另一工作树的仓库内路径相同时，生成共同仓库检索键；保留独立的绝对路径键。当前登记共同目录跨项目有歧义、元数据未记录／非法、根是data／alias时不生成共同键。
- 相对路径只沿原生记录目录及固定工具参数定位，按同一来源文件和逻辑片段向前继承；缺失观测、非法或不可用声明阻断。不用可变session.cwd补造旧目录，不解释shell、变量和命令替换，不读取当前工作区或运行Git。Windows盘符、UNC及分隔符作词法处理，组件大小写不擅自等价。
- `paths.py` 保存结构化字段和引号／反引号中的完整含空格路径；`working_set.py` 和生产Worker两轮补查使用定位后的检索键。直接ID、标签、路径和前片段的原优先级、完整范围分组及3000 token预算继续执行。
- `linker.py` 用仓库内路径键核对跨会话文件版本，但完整范围、不同会话、摘要算法和摘要相等仍分别必要。不同工作树里的同路径不同字节不作为同版本，物理版本记录不合并，模型新记录仍candidate。
- 路径策略进入持久工作器配置、非pass1调用及链接的来源缓存身份。旧原件、候选、人工审核和版本不改写；没有数据库迁移或新界面入口。
