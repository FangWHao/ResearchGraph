# 前端精确时间与未知状态验收

日期：2026-10-10。起始提交：`e81a0ea82466931ac260672c43004e77e0efe4fb`。

本轮修复采用与证据状态的历史误读。发生时间按完整微秒比较，入库时间和记录编号只用于时间线展示顺序，不选择事实。同刻相反的有效记录返回冲突；任何有效已确认且未被替换的记录缺少可解析发生时间，返回发生时间未知。未知范围分别返回采用范围未知、证据需复核。候选、已驳回和已替换的记录继续保留为历史，不决定当前状态。

## 实现与边界

优先读取后端的 `occurred_at_utc`、`recorded_at_utc`。显式空值是权威未知，不回退原字段；只有旧接口缺少规范字段时，才严格解析带时区的标准公历 ISO 时间。前端不猜测 Python 接受的紧凑日期、周日期、逗号小数或秒级时区偏移。规范 UTC 字段保留这些原格式的后端解析结果。

`exactTime.ts` 用整数微秒比较，核对真实公历日期、闰年、时区换算与公元 1 至 9999 年边界，支持 Unix 纪元前时间。单测覆盖公元 1 年、99 年、1000 年、负一微秒、非法闰日、UTC 越界、无时区、尾部 LF／CR／CRLF 和超过六位的小数。人工证据编辑枚举保持原六种合法状态；显示用的独立映射包含发生时间未知和记录冲突。

过程组只折叠视图，不赋一个成员的采用或证据状态给整组。验收核对折叠期间的全部保留记录、内部与边界关系及原文引用；展开后恢复原成员的微秒状态与完整节点位置和关系。

问题卡中的方案未登记证据事件时仍显示未评估。合成库只向发现登记证据事件，符合对象种类要求；没有为覆盖界面制造方案证据。未知范围的问题卡显示范围未知、证据需复核，不进入当前采用分组。

## 真实本机 API 与视觉验收

专项独立启动父任务维护的 `tests/state_time_browser.py`，端口 9794、临时合成库、生产 API。启动前核对端口占用，退出时只对自身服务发送 SIGINT 并等待清理。不读取真实会话，不调用模型，不修改原件。原 8791 合成库与新库隔离。

四项验收直接读取真实接口，没有替换或模拟 API 响应：

1. 核对 11 类发现／方案的前端状态与 `/api/semantic-graph` 权威状态一致。后发生微秒先插入、较早微秒后入库仍选择后发生状态；同刻不同时区相反记录冲突；缺失、无时区、非法日期和 UTC 越界的规范值为空。真实 Python 紧凑日期、周日期、逗号小数得到同一规范时间，秒级偏移按后端 UTC 结果处理，原字段保持原值。
2. 核对研究图发现的采用／证据诊断，以及问题卡的方案状态与分组；未知或冲突不进入当前采用。
3. 同一修订折叠微秒发现与链中间节点，保留 13 条原记录和三条内部／边界关系。实际打开阴性证据原文，逐字核对 `/api/evidence/{id}` 的 UTF-8 窗口并计算 SHA256；展开恢复全部节点位置、关系和原成员微秒结论，重新查询图内容完全相同。
4. 桌面入口切入空项目，旧方案消失，再返回原项目；390 宽显示未知范围、冲突及折叠后候选原证据。候选缺时间原文仍可查，不能污染有效阴性状态。原文窗口与引用哈希相符，页面无横向溢出。
