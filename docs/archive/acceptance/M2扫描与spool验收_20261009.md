# 扫描与 spool 验收 · 2026-10-09

本轮实现 §2、§6.1/§6.5/§6.6 与 §10 的采集轮询、提示消费和备份恢复基础。开发使用合成 fixtures，没有读取完整真实会话、发送模型请求、安装钩子或修改用户工具配置；真实 M1 效果门槛与完整 M2 仍未通过。

## 行为与证明范围

scan 持久登记日志文件/目录；以后可不带路径持续轮询，递归发现新 .jsonl。已显式 import 文件也继续扫描，项目由显式来源与现存记录决定，未知保持收件箱。重叠来源存在不同解析器/项目时拒绝读取，不依赖选择顺序；目录中的符号链接不授权外部路径。同文件并发扫描、单次消费和持续轮询各有系统进程锁，停止后系统释放。

spool 库入口保留输入原始字节，fsync 与原子改名后才可消费。原件复制到对象库，再与不可变回执、工作登记事务提交。日志游标完成后确认，才清理内容仍匹配的队列文件。未知事件和坏 JSON 保留原件；未归属、日志未出现或忙继续等待。每轮最多消费 100 条，更新时间轮转避免前页等待项长期阻塞后续就绪项；失败默认跳过，显式 scan --retry-failed 重试。临时文件不消费，大于 4 MiB 或符号链接提示保留并报告 spool_held_files，没有把它当作成功。

真实子进程 SIGKILL 在日志提交后、提示确认前发生；重启后旧事件仍在，新增事件正常导入，原回执完成，重复扫描新增为 0。另验证：在已提交回执后移除队列文件，backup 的副本仍能由回执对象恢复消费；备份包含全部回执原件，不仅复制 raw_events 对象。这些测试不是本机真实全量会话的 M2 验收。

health.ingest 展示登记来源、已知路径、回执、未完成与失败数。jobs.running 表示未提交消费记录，不证明进程存活。钩子输入的未知字段完整保留，里面的命令仅为资料，不执行，不生成研究候选。版本 6 升级失败时回滚表、索引和版本，原事件保留，不补造来源或回执。
