# 钩子失败账本验收

本轮补§9的钩子失败报告诊断，遵守§2、6.1、6.8、10、11和15 B／D。开始核对进度、相关章节及决定；73430d1基线恢复包已验证。整项目清除沿用户选择，只对临时合成项目测试。原规格不改，模型调用为0，没有读取真实完整会话。

## 保存和读取边界

`rg.ingest.hook_errors.collect` 由正常扫描循环调用。三个表在迁移20中建立；报告、观测只追加，来源身份不可改，游标可推进。来源及报告与观测原子提交，强制退出后继续同一来源不丢报告。轮换前历史保留，SQLite备份可在没有错误源日志的情况下查询。

错误只存协议元数据，不进L0、对象库或prompt。未知错误正文不复制，非白名单类只存摘要；日志目录／文件链接、非普通文件不读取。固定位置是管理目录内的错误日志，不遍历客户端会话目录。钩子生产入口没有改动，实际命令保持静默exit 0。

每批1000行、单行4096字节。末行残片不推进；积压与超长行明确有未读字节，超长行不截断。前缀和已提交边界摘要不能保证发现中间任意覆写。未知类、非法行、漏采状态分别保留；完整实际失败历史始终未知，报告数不等于实际失败次数。

`hook-errors` CLI、`/api/hook-errors` 及健康统计只读查询数据库。project仅验证项目，口径为整个管理目录；分页冻结观测ID及报告截止，后来追加不改变旧页。没有观测时为未知，空文件为零条已采集报告。状态变化时间不证明进程活跃。整项目清除保留仅运维的无正文全库元数据，不把它误归属到单个项目。
