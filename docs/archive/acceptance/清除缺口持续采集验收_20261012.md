# 清除缺口后的持续采集验收

本批使共享来源在整项目清除后继续保存后续公开记录。迁移32把清除缺口另存为无正文的不可变字节边界，原件摘要命中、续接身份及游标在同一事务提交；原始事件与原生别名不改写。旧停留式采集是前批合同，本批仅对可核对的完整记录升级。

## 处理合同

完整物理原件精确命中工具命名空间摘要时，采集先登记缺口，再提交游标；不保存该原件、解析正文、登记搜索或派生L1。新逻辑身份保留真实工具、原生编号和Agent，不带旧cwd。显式整会话项目可继承；已经正式分片的来源，新尾部继续进收件箱。再次分配后从当前位置追加续接边界，旧归属不回写。

清除共享来源中的原记录时，主删除事务也登记原来源缺口。父线程及Claude父链补记只越过已提交、连续的清除边界；无法证明的空洞仍不能推进。不完整末行不复制，spool仍queued；完整删除记录已审计且其余内容已保存时才可done。损坏／缺失摘要索引及整来源封禁仍拒绝采集。

有效归属依次采用正式记录映射、最新续接身份及物理身份。已清除的最新身份不使投影倒退到更早身份；整来源最后被清除时，缺口和续接账本一起移除。共享对象仍被其他项目使用时不进入全局封禁；来源内删除边界独立保留。

查询和瘦身上下文、工具结果配对、镜像配对与目录线索按边界隔离；保留的原始别名可以在有效投影失效，公开正文仍独立进入搜索与覆盖账本。页面观测完整仅表示保留记录观测齐全；不能据此声称物理来源没有清除缺口。

## 接口与界面

片段查询新增当前来源的 `privacy_skipped_records` 和 `privacy_skipped_bytes`，无需回读原件。计数和最新续接身份参与读取摘要，旧分页在缺口变化后返回409，即使没有新增保留记录。目录在缺口处明确 `privacy_gap`，再次出现有效原生目录声明后才恢复可用线索。

前端展示记录／字节数，并说明缺口两侧分别处理。首末选择必须每条物理记录首尾相接；跨缺口时预检和保存不可提交，不自动扩大选择。旧接口没有计数时显示未知；续页计数变化时拒绝混页并保留已读页。
