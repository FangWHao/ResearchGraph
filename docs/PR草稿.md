本机 Codex／Claude Code 会话已接通项目登记、持续采集、提取及桌面查询。Windows工具报告原先因反斜杠和盘符丢失文件根关联，新派生现在支持盘符、UNC、相对路径和POSIX写法；对应记录目录定位文件，无效明确参数不回退会话末尾目录。Claude请求与报告指向不同文件时保留冲突和已知前像，不发布后像；Codex回执允许同一物理文件的相对／绝对写法，重复或不同文件拒绝证明成功。正文版本仍为候选，不读取当前文件补旧历史。

同一Git项目在两个工作树中使用绝对／相对路径时，提取工作集可通过已登记共同目录和仓库内路径召回已有方案；缺失／非法声明及跨来源／片段不借用。物理路径和版本分别保留，同版本跨会话候选还须匹配完整范围、算法和摘要，模型结果仍为候选。共享词法策略进入持久配置和缓存身份。

首次打开可直接创建项目，表单仅名称、绝对工作区和本地采集开关；列表加载／失败不冒充空库，保存失败保留输入，同名同根重放返回原项目。项目与根事务发布，重叠的不同项目拒绝创建；来源明确勾选才登记服务用户已有的默认共享目录，缺失／不可用分别提示，项目仍保留。创建不安装钩子、不读会话正文、不授予模型外发。

新增包含界面的通用桌面wheel，从任意目录运行，无需用户安装Node／pnpm。安装包优先自身资源，源码使用自己的构建目录；默认不会选择当前目录中无关页面，缺少界面时在创建数据目录／启动后台前拒绝。普通后端安装仍轻量，桌面构建由脚本显式包含静态资源；新增CI构建及仓库外安装检查。

既有 `client-install` 合并项目技能和MCP，`start` 管理扫描／spool／离线派生／文件处理，明确加 `--extract` 后串接模型流水线。保留外发许可、128k可调实测预算、候选约束及每日额度。只读 `impact` 固定项目、完整范围、双截止和修订，确认关系与候选／报告依赖分开，不改变科研状态或推定完整实际I/O。界面仍默认三个主入口，影响入口收在详情折叠区。原生Windows Codex基本四回调已验收，状态读取与后台退出故障已修复。
