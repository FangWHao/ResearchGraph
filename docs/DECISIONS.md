# 开发决定（只追加）

## 2026-10-09 · 开发顺序与试点边界

- 决定：依据 §0、§12，先实现可离线测试的后端；真实试点效果未通过之前，不提前开发 Web 界面。Atlas 是试点，试点原项目不写入、不执行其中脚本。
- 理由：用户要求完成开发，规格又明确用提取可行性决定后续路线；自动化测试不能替代人工参考标注和两周真实使用。
- 放弃：先做完整图界面，再用合成案例声称所有里程碑完成。

## 2026-10-09 · 原始记录中的多个内容块

- 决定：在规格的 raw_events 中增加 record_index，将唯一键扩展为 `(file_instance_id, byte_start, record_index)`；同一 JSONL 行中的文本、工具调用和结果分别保留事件，原文共用内容寻址对象。
- 理由：Claude 单行可以包含多个不同种类的内容块，原唯一键不能表示这些独立事件；引用仍使用相对整条原始行的 UTF-8 字节位置。
- 放弃：只选一个内容块、丢弃其余块；或将工具调用混入正文导致切片丢失调用边界。

## 2026-10-09 · 模型计数与远程发送

- 决定：采用 OpenAI 兼容的 Responses 接口及提供方输入计数接口。兼容服务不支持实测计数时，停止发送，不用字符估算或试发生成请求。模型与地址必须由配置指定，不把规格里的默认模型名称当作已验证可用。
- 理由：§7.2 要求每次模型调用前实测完整请求 token；§11 要求项目默认不外发，遮盖后才可发送。
- 放弃：只计正文而漏掉工作集/schema；使用字符数除以四；对任意第三方假设兼容性成立。

## 2026-10-09 · DeepSeek 实测后的协议适配

- 决定：保留通用 OpenAI Responses 适配器；用户指定的 DeepSeek 使用同一官方服务的 Anthropic 兼容计数与消息接口，计数和生成传递相同正文、系统指令和工具 schema。
- 理由：OpenAI 风格计数入口实测 404，兼容消息计数入口实测 200。使用同一消息协议可以在生成前实测完整输入；生成后的实际输入合计包括缓存读取与创建部分，不能只计缓存未命中的 input_tokens。
- 放弃：生成后才根据 usage 补计预算；用另一模型的 tokenizer 猜测；为保持表面接口形式而绕过计数硬规则。

## 2026-10-09 · 引用与失败处理

- 决定：要求模型照抄整个原文窗口及其已给出的 UTF-8 字节范围。校验器仍逐字与摘要校验，不修正或猜测模型的错误偏移。L1 对象尚未实现时拒绝用 L2 对象冒充 consumes/produces 的端点。
- 理由：真实合成测试暴露了局部中文偏移错误与未定义临时 ID。明确约束后通过本地严格校验；失败时拆片或进入人工队列，保留覆盖缺口。
- 放弃：把字符位置当字节位置；默默接受错误引用；用字符串模糊匹配把错误结果修成已确认事实。

## 2026-10-09 · 缓存、账本与建库原子性

- 决定：工作集排除本片段及后续片段自身产生的未确认候选；成功的会话处理缓存同时包含原文身份、模型、提示、schema 和人工复核版本。重试子片段也纳入覆盖账本，全部完成才缓存成功。每日用量先保守预留，拿到提供方用量后结算；计数失败不发送生成请求。建库在单个事务中逐句执行 schema。
- 理由：避免自我反馈使重复提取产生新候选；防止失败的父片段掩盖子片段缺口；防止建库中断留下已写版本号但缺表的数据库。
- 放弃：只按源文件名缓存；让新提取覆盖人工确认；直接使用会隐式提交的 executescript 完成建库。

## 2026-10-09 · 真实参考记录与保存授权

- 决定：Atlas 的规则定位结果保持候选，人工核对前不标为正式参考记录。真实派生材料保存在仓库之外；复制到新的持久目录被自动审批拒绝后，保留原临时位置并等待目的地授权。
- 理由：规则候选不能冒充人工标注或用作独立效果评估的分母；真实预览可能含敏感信息，不能绕过数据转移审批。
- 放弃：把 48 条规则候选改为 human_reference=true；将真实原话塞入 Git fixtures；通过其他目录间接绕过拒绝。

## 2026-10-09 · 试点持久目录获得授权

- 决定：用户明确同意保存到 `/mnt/d/ResearchGraphPilot/20261009` 后，复制 `references.json`、`人工参考作业表.md`、`试点问题草案.md`，不覆盖内容不同的同名文件，并逐份校验 SHA-256。
- 理由：具体目的地和数据转移已获授权，原有审批阻塞已解除；持久材料仍保留在仓库外，人工标注状态不变。
- 放弃：读取真实作业表原话进入开发上下文；以保存成功代替人工验收。

## 2026-10-09 · 用户调整输入预算

- 决定：用户明确选择“128k 默认，允许调高”，因此完整请求输入默认改为 128000 token，通过 CLI `--input-budget` 调整。工作集和指令/schema 各保持 3000，封装余量 2000，输出保持 4000；发送前仍实测完整请求。此决定覆盖原规格 §7.2 的 24k 数值，不取消其他硬规则，源规格保留原文。
- 理由：压缩前累计上下文不等于当前回合新增内容；本流水线处理增量事件，不重复发送整份历史。当前 DeepSeek `/models` 实测窗口为 1048576；预算加输出必须在该窗口内，元数据缺失时停止生成。窗口容量不能代替人工参考评估。
- 放弃：把全部累计 API 输入量当作新增内容；固定只允许 24k；把模型 1M 容量视为无预算或无效果评估的许可。

## 2026-10-09 · 重叠的证据归属与超长回合

- 决定：Segment 区分本片段事件与 `context_only` 重叠事件。普通用户回合携带完整上一回合；超长回合内部的延续片段与重试子片段携带最近不可拆工具组或有字节边界的正文窗口，并记录未携带位置。覆盖账本只记本片段，候选必须至少有一条当前窗口证据；同一 event_id 内也按字节窗口区分。
- 理由：支持“先暂停它”等跨回合指代，同时防止重叠让旧决定重复入库，或让长正文后半段被误标为已完成。工具调用与结果保持同组，截断/超预算仍二分重试。
- 边界：完整上一回合本身超预算时不截掉它，重试仍放不下就进入人工队列；可以人工调高预算后重跑。延续窗口缺失的早期上下文是明确通知，不是模型摘要，也不充当证据。
- 放弃：用模型写的摘要替代重叠原文；只按 event_id 判断长正文的证据归属；静默丢掉上一完整回合再标记成功。

## 2026-10-09 · 显式范围与工作集优先级

- 决定：提供重复 `--scope 字段=值` 的完整范围输入。范围按已有状态逻辑使用完整字典相等，工作集筛选和模型输出都必须一致；模型不能加 axis/topic 等字段改变范围。不指定范围时保留带 scope 的检索线索，明确不声称已完成同范围筛选。
- 理由：真实合成调用曾在同一对象上输出不同的范围字段组合，虽然引用合法，却会使采用/暂缓状态无法对齐。不能从目录或模型摘要猜测研究范围。
- 决定：工作集按直接 ID、字面量 FTS、同文件路径、本会话先前候选排序；跨范围状态分别计算，候选不改变人工确认状态。长正文同一事件内使用字节边界区分已处理与后续窗口，不用无关对象回填。
- 放弃：以范围字段子集匹配自动合并状态；让 FTS 运算符混入用户文本；通过执行历史命令识别路径；把全项目最新候选当作默认相关对象。

## 2026-10-09 · 候选位置与数据库迁移

- 决定：通过原始 JSON 路径定位各内容块，解码字符位置映射回原始 UTF-8 字节，模型只选已给出的范围。规则独立召回的位置与模型位置一并保存在版本 2 的 `candidate_locations`；迁移以事务执行，不改写 L0。
- 理由：相同文字可以出现在多个内容块，首个字符串匹配会把决定指向错误原话；转义字符串的位置也不能按解码后字节直接计算。pass2 只取回登记的候选正文与有限工具原文。
- 决定：JSON 转义后的隐私与 rg 标记同样遮盖。邮箱表达式限制词起点，避免长工具行上从每个字符重复尝试匹配。
- 放弃：模型计算偏移、模糊修正错误引用、把瘦身摘要的位置当原文位置、直接重建旧数据库。

## 2026-10-09 · 逐对链接与概览边界

- 决定：不同会话、相等完整范围下，以标签 FTS 或相同路径/算法/摘要的文件版本选候选对；逐对只给两张结构化卡片和一侧最多 2k token 原文。将 §7.8 的每次 ≤4k 保守落实为实测输入 ≤3000、输出 ≤1000，总量 ≤4000。
- 理由：不能把两个完整会话同时送入上下文，也不能把同标签或文件版本当作相同对象的证明。未知范围不参与；独立 attempt 的合并和非法关系拒绝。合法链接仍为 model_inference candidate，缺失时允许 none。
- 决定：概览每页直接读 claims，记录输入 ID 与模型引用 ID；不读取 L0，也不读取任何已生成摘要。输出以 `<rg-context>` 包裹，拒绝模型正文嵌套或关闭该标记；所有页成功后原子发布，失败保留既有文件。
- 放弃：跨会话正文一起输入、按检索线索自动合并、递归合并摘要、用概览作证据或工作集、用候选决定描述已确认采用。

## 2026-10-09 · GitHub 初始维护

- 决定：按用户维护仓库的要求，从远端已有 Apache-2.0 初始提交建立独立开发分支，提交可复验后端、中文规格与文档、合成 fixtures 和离线 CI，建立草稿 PR。保留许可证，主分支由评审合并。
- 理由：远端当时只有 LICENSE，本地代码尚未入库；先将验收结果与剩余门槛一起做成可审阅版本。维护请求不等于安排无人值守定时任务。
- 决定：凭据、真实材料、统计清单、环境、缓存、数据库和本地 Word 归档不提交；对提交清单做实际密钥匹配检查。CI 不调用远程模型。
- 放弃：直接覆盖主分支、把完整产品尚未完成写成已发布、上传真实试点材料或凭据、为追求 CI 绿灯使用生产模型密钥。

## 2026-10-09 · 远端写入认证不足

- 决定：连接器两项写入都返回集成权限 403、本机 HTTPS 与 SSH 认证均失败后，保存本地维护提交、可审阅 PR 草稿和完整 Git bundle；不把本地 CI 检查写成远端 CI 通过。
- 理由：用户已授权维护，当前缺的是 GitHub 的技术认证，不是任务授权。full access 解决本机文件访问，不会提升 GitHub App 权限。SSH 检查仅使用官方公开主机键的临时校验文件，没有改动用户 SSH 设置。
- 放弃：将 DeepSeek 凭据用于 GitHub、读取或外发私钥内容、修改账号鉴权设置、声称未推送的分支已经上线。

## 2026-10-09 · 链接调度、暂停与恢复

- 决定：版本 3 新增 `link_progress`，按候选对与提供方、模型、提示/schema 请求头、有效输出上限记录进度。`--limit` 只限制新尝试，已完成项直接跳过；失败项默认保留人工队列并继续后续页，只有显式 `--retry-failed` 才重试，同一任务不重复建人工条目。
- 理由：原先每次只取前 50 对会使后续对永远无法到达；缓存仍先取原文、计数也会浪费预算。持久进度支持跨进程续跑和新增对象；已有关系提交成功但进度写入前中断时，可通过成功运行恢复，避免重复候选。
- 决定：每个项目使用系统的非阻塞进程锁，不在模型调用期间持有 SQLite 写事务。进程退出或被杀后系统释放锁；锁文件存在本身不表示进程活着。
- 理由：同一项目两次链接不应同时生成同一关系，但采集须保持可用。Linux 子进程终止后重新取锁已经实测；Windows 分支仍待目标平台运行验收。
- 决定：每日预算不足用独立异常暂停，保留 pending 和提取覆盖缺口，不触发二分或人工失败。链接计数/提供方暂不可用也暂停当前对；恢复后再执行原命令。成功重试清除运行和暂停通知上的旧错误字段。
- 放弃：永久缓存前 50 对、用已完成项消耗下一页额度、默认不断重试校验失败、按锁文件年龄删除锁、跨远程调用保持数据库写锁、将每日限额当作内容超长继续拆片。

## 2026-10-09 · 输入标识符与无关系输出校验

- 决定：遮盖按输入结构递归执行，只在程序规定的路径保留生成的 pair/segment/entity ID；原文、标签、范围、理由及同名自由文本字段保持严格遮盖。
- 理由：66 对合成测试中，一个摘要包含手机号形状的数字，被整体字符串遮盖后导致模型照抄的 pair ID 与原 ID 不同。放宽手机号正则会漏掉原文中的号码；精确元数据路径避免此问题，也不会让原文里的 `pair_id` 键获得例外。
- 决定：链接 `relation=none` 时 source/target 必须为 JSON null；提示词和 JSON Schema 一致约束，本地仍做语义校验。DeepSeek 曾返回 none 加两个对象端点，该结果已经作废并保留失败记录；不将端点自动改成 null 以伪造通过。
- 放弃：对整个 JSON 放宽隐私正则、只按字段名免除遮盖、依赖模型更正 ID、接受 none 中声明的端点、删掉失败接口记录只保留成功。


## 2026-10-09 · 本机 GitHub 认证恢复路径

- 决定：优先通过官方 GitHub CLI 的浏览器设备授权恢复本机 HTTPS Git 认证；使用用户目录下的独立安装，并校验官方下载资产 SHA256。
- 理由：现有 helper 仅为内存 cache，缺少可用登录工具；设备授权允许账号持有人直接在 GitHub 登录。待维护提交包含 GitHub Actions 配置，因此在默认登录范围外申请 workflow 范围，实际授权由用户在 GitHub 完成。
- 放弃：要求用户把访问令牌贴进聊天、读取其他服务的密钥、修改主分支、为了测试认证而创建远端对象。连接器权限与本机凭据分别验证，不把本机登录当作连接器修复。

## 2026-10-09 · 提取监控与调用尝试账本

- 决定：数据库版本 4 新增每次调用尝试的账本，保存项目、模型、片段、输入/输出预算、发送前实测、实际用量、发送尝试标记、状态与结束原因。逻辑运行仍用于缓存；重试不能覆盖已结束的旧尝试，缓存命中不新增调用或用量。
- 理由：旧运行记录只保留同一输入的最新重试，无法证明实际失败率与累计用量。最终状态由本次尝试的显式 ID 写入，避免两个 worker 交错时误写另一条尝试；claims 和运行成功状态在同一事务中提交。此记录方式不等于已完成全队列并发调度。
- 决定：利用率有实际输入时用实际值，否则用发送前实测值。按阶段统计；规格的“片段占比”按项目和片段 ID 去重，重试或补查只贡献一个片段，历史中任一次超过 80% 即记该片段为高利用率。超过 80% 的片段占比严格大于 10%，以及校验拒绝率严格大于 5% 时给出本地告警。
- 决定：引用失败单独分类，校验拒绝率统计已结束的 ok/invalid/lookup 输出；截断、污染、预算违规、每日额度暂停、服务失败另列。没有可用分母时比率为 null。此指标不是找回率，也不能作为真实引用成功率。
- 决定：费用按 §7.10 的每日 token 额度报告，不猜货币价格。额度计数保持全库；项目筛选只作用于提取指标与覆盖缺口。已发送尝试缺少实际用量时保留未知和保守预留。跨 UTC 午夜按额度预留日归属；health 的上限参数必须与 worker 一致，不把它冒充持久的全局配置。
- 决定：迁移不补造旧尝试，明确列出缺少历史的运行数；未结束尝试不能证明进程仍活着。覆盖缺口按事件阶段分页，包含可打开证据的事件 ID，不输出原文。
- 放弃：重试成功后抹掉失败、将计数失败算成零费用、把每日额度暂停误报为输入超长、用每次重试充当一个新片段、从剩余文件推断进程存活、用旧运行最新计数还原不可知的历史账单。

## 2026-10-09 · 并发提取、响应缓存与重复入库

- 决定：沿用链接阶段的系统非阻塞进程锁，新增同会话提取、同模型任务和同项目概览的锁。模型任务键加入项目 ID；不同会话、不同项目仍可并行。竞争返回独立的 TaskBusy，不算提供方失败，不拆片、不建人工失败条目、不将覆盖缺口标为完成。
- 理由：同会话片段必须先后构造工作集；只依赖唯一 job_key 不能阻止失败重试或已建立运行被两个进程同时调用。锁覆盖实际计数和生成，但不跨远程调用持有 SQLite 写事务。进程退出后系统释放锁，不根据文件年龄或存在与否判断存活。

- 决定：Claude 的 originalFile 与严格核对的 structuredPatch 可生成编辑前后候选文本，输入声明与报告不一致时只保留已知内容和缺口。无末尾换行边界、混合换行、错误 hunk、工具错误及人工干预均明确记录。只验证工具报告，不读取当前文件修复旧版本，不推断唯一作者。
- 决定：文本版本使用 sha256:tool-utf8、tool_reported_utf8、direct_record、candidate，区别于经过验证的物理文件字节。Codex 更新/删除仅保存补丁；成功 Add 可以保存报告的新增文本，但既有文件可能被覆盖，编辑前版本仍未知。对 U+2028 等正文字符不使用通用 splitlines 重新构造文件。
- 决定：派生工作队列与事实写入同事务，崩溃不动 L0 游标，重跑幂等；未归属或缺调用进入等待，失败只能显式重试。每次处理 1–1000 条，默认 100，写入使用数据目录进程锁；等待项更新排序时间以免长期阻塞。版本 7→8 升级只加结构，旧记录不补造运行或版本。备份同时包含候选内容和补丁对象，删除原目录后仍能展示差异。
- 决定：证据 API 对运行、观察、编辑和版本返回部分清单标记；差异每份及同事件合计最多 64000 UTF8 字节，每份最多 2000 行。运行命令最多展示 8000 UTF8 字节，并标明预览与完整字节数，原文仍完整保存在 L0；观察明细只重复命令摘要，避免复制长正文。超限明确不可展示，不截断后声称完整。已有瘦身缓存升级至版本 2，撤销从任意正文提取退出码的旧摘要，保留 L0 不变。
- 理由：直接记录应让可证实的信息和缺口同时可见。工具报告的文本不是物理字节校验，成功退出也不是完整复现清单。前端子 agent 按用户授权接入上述证据，命令只阅读，运行 I/O 版本未记录时明确说明。
- 放弃：假定缺失结果就是失败、将 tool_result 的任意 JSON 或 stdout 当作退出状态、拿当前文件补旧 preimage、将补丁当成完整前后版本、拿路径和时点当作者证明、把候选升级为人工确认，以及把本轮合成案例当成完整 M2 验收。


## 2026-10-09 · 人工问题入口、未知范围与重试身份

- 决定：本轮交付 §8.1 的人工 question，CLI 与本地令牌 HTTP 共用服务。文字原样留在程序生成的显式输入 JSON 对象中，登记工具 rg 的人工载体会话和虚拟来源，再以 manual/human/confirmed 写统一 claims；原文、证据、问题和不可变回执同一事务提交。
- 理由：§2 要求模型不可用时仍能人工记录，并区分问题确认与采用、证据、运行状态。人工命令不依赖模型推断；虚拟来源不能被扫描器当成本地日志路径、被健康页误报为来源删除，或再次提取成新候选。
- 决定：没有范围的人工问题保存 SQL NULL 和 JSON null，人工问题追加修改也允许明确 null。模型 schema 与其他类型的修改继续要求完整范围。现有问题 schema 的独立副本仅放宽人工问题的范围，仍要求类型、对象和可核对原文。
- 理由：问题可以先于数据版本和分析步骤出现；§2 允许缺失保留未知，“当前采用必须带范围”继续成立。修改必须显式提交 scope 字段，不能因漏字段清掉已知范围。
- 决定：UUID 标识一次人工意图；原意图摘要包括项目、文字、完整范围、人工身份及显式回填时间，不包含传输重试的图版本。事务内先检查既有回执，再校验新写入的 expected_revision；既有意图返回当前版本及原记录，不撤销后续人工复核。相同 UUID 内容变化返回 409，独立 UUID 允许相同文字再次记录。
- 理由：成功写入后网络响应丢失仍可恢复一次；旧版本冲突和重复提交不能伪造新问题或恢复被驳回的记录。文本相同不等于用户进行了同一次记录。
- 决定：人工入口以本机操作/令牌为信任边界，接受非空 human 身份，拒绝 model/agent 身份；不将此入口注册为 Agent MCP 工具。开发只验证合成数据，不代用户创建真实科研判断。
- 放弃：用字符数推测 token 并调用模型记录人工问题；用 unknown=unknown 伪造范围；按内容去重独立问题；重试覆盖原文或复核；将人工问题确认扩张为采用或发现成立；将客户端自称身份当作操作系统的身份认证。
- 待定：note 没有 §5 对应类型，DECISIONS 也未定义，已按 AGENTS.md 提问；它的表示待用户答复。decide 的对象歧义复核与客户端包装留在后续任务，不以 question 基础入口宣称整个 §8.1 完成。


## 2026-10-09 · 人工问题前端草稿与迟到响应

- 决定：问题创建由用户在当前明确项目主动输入；草稿按项目保存在页面内存，保存成功刷新图并可查看记录及原文。网络错误、409 和重新鉴权保留草稿和同一意图 UUID，刷新只读取数据，保存仍须人工点击。内容、范围或记录者变化使请求身份改变。
- 决定：旧请求延迟成功只刷新数据，只有返回编号仍匹配该项目当前草稿及内容/范围/人工身份才清除已保存草稿；关闭表单和打开记录另外核对当前项目、鉴权及表单归属。正文/范围编辑立即撤销旧意图编号，跨项目切换不搬运草稿。
- 理由：一次成功已经发生而响应丢失时，重试应找回原记录；关闭或切换后旧成功不能清掉用户新写的内容，或者打开另一个项目的记录。父任务审查发现全局 Escape 与在途响应组合可能丢草稿，修复后用真实 HTTP 延迟响应验证。
- 放弃：响应到达无条件清空表单；每次点击都生成新 UUID；409 后自动重新提交；把页面内存草稿声称为关闭页面后仍可恢复的存储。

## 2026-10-10 · 人工决定歧义、未知范围与可选纠错

- 决定：§8.1 的四种人工动作共用本地记录服务，整个项目的有效 entity_version 按完整范围取版本，人工确认优先于候选。ID 精确优先，名称完整相等；显式范围只接受完整相等。省略范围时不从目标推定范围，唯一身份直接确认决定，但未知范围不能成为当前采用。人工问题和决定的独立 schema 可保留 null，模型 schema 不变。
- 决定：同名及未知选择器保存 decision_event candidate、target=null。decision 实体仅承载项目归属，没有 entity_version，不当作研究方案。选择对象入口只能选同项目、原完整范围内的有效对象；不能改动作、理由或范围。追加确认替换版和复核动作，保留原发生时间及两份原文证据，选择发生时间与入库时间另存原件。普通确认、批量确认与通用修改拒绝未解析目标，数据库触发器禁止确认 null 目标。
- 决定：人工问题、决定和选择对象的 UUID 跨操作保护，由 BEGIN IMMEDIATE 事务核对不可变意图和回执。相同意图的并发/丢响应重放只返回原记录及当前版本，旧重放不恢复后来驳回的记录；不同操作或内容返回冲突。原件、引用、记录、复核与回执原子提交，备份包含所有原件。
- 决定：对象检索先核对全项目有效版本，再按字面量和实体分页，不用图上限或当前工作集判断唯一。长标签预览最多 8000 UTF8 字节、明确截断与总字节，搜索仍匹配完整标签。未知范围的当前采用判定在前端、工作集和规则中保持一致。
- 理由：人工补记不能把未知归属伪装成唯一对象、把局部范围扩张为完整范围，或把确认决定当作确认证据。人选择的身份须可独立追溯，同时允许原研究判断的时间早于复核时刻。
- 放弃：默选第一条同名对象、用范围子集匹配、按图前 2000 条宣称唯一、用名称新建伪对象、复核时自动补目标范围、用通用编辑修改目标、重试恢复已驳回事实。
- 产品方向：用户提出理想日常体验为零人工干预。自动采集、提取、证据关联与查询应构成默认流程；人工入口作为可选补记和纠错，歧义仍可保留候选并参与检索，不强迫逐条人工审核。现行模型候选及独立规则确认要求继续执行；真实自动完成比例与误读率尚未验收。

## 2026-10-10 · 持久自动队列、截止事件与持续处理

- 决定：省略会话的 extract 使用版本 11 持久队列，watch 串接已登记来源扫描、spool、L1 和提取；单数据目录一个系统锁调度器，任务状态与只追加事件分开，任务输入不可修改。网络期间不持有 SQLite 写事务。人工载体和未归属/未外发授权项目在计数前跳过。
- 理由：用户期望日常运行零人工干预，逐个指定会话无法形成持续流程；系统互斥可证明旧自动执行器已经退出，比运行字段或时间推断可靠。领取编号防止过期执行者覆盖新结果；实际 SIGKILL 验证未知用量预留不释放、锁释放后恢复。
- 决定：任务固定最大原始事件，worker 仅处理该前缀；晚到内容入下一任务。已登记计划跨截止事件时等待完整窗口。新内容或静态配置替代旧待执行任务并追加取消历史；审核变动本身不重排无新增内容的会话，原显式 worker 的审核缓存配置和保护人工记录合同保留。
- 决定：额度暂停等下个 UTC 日，原文追加与恢复旧配置保留同配置等待；忙碌更新排序以继续其他会话。部分失败默认保留，只有显式 retry-failed 重试；watch 仅启动首轮重试。完整成功响应恢复仍校验来源，同提供方/模型/正文复用实测分量计数，新生成完整请求每次实测并核验窗口。
- 放弃：不断扫描即重发全部历史、review_id 变动导致自动互相触发、按锁文件年龄抢任务、网络期间占数据库事务、用运行记录作为存活证明、取消旧任务后删除失败历史、日额度暂停每天以前反复尝试、自动把候选全部确认。未安装系统守护服务或个人客户端设置；图关联与问答还需接续。

## 2026-10-10 · MCP 返回上限与本地编码

- 决定：用户对计数口径问题答复「要不算了，不限制这一个？不行的话就本地精确 tokenizor」。本轮取消 §7.11 固定 1500 token 的 MCP 返回上限，源规格保留。普通查询保留有限页长和原文字节窗口；状态卡按调用方预算计完整标记文本，默认 2000、可调高，协议封装单独处理。
- 理由：Agent 可以按任务读取详情，不必为固定小上限频繁取回同一条记录；分页和明确引用继续让读取可追溯。用户要求优先于原规格数值。高优先级逐项尝试保留详情，放不下则保留 ID、独立状态和范围，连引用也放不下则推进下一页或明确要求调高，不能默默跳项。
- 决定：本地默认 cl100k_base，可按客户端启动参数改为 o200k_base。正式词表压缩随包提供、按原件 SHA256 校验，计数只读本地，不隐式下载或外发研究文字。标明编码，MCP 元数据记录标记正文 token 数；不冒充 Claude/DeepSeek 的计数，模型完整请求计数规则不变。
- 放弃：坚持原固定 1500 上限；按字符数估计；把另一个模型的编码计数当提供方实测；查询首用时联网下载；把遗漏详情或不完整 ID 列表当完整历史。

## 2026-10-10 · 只读入口与历史状态

- 决定：CLI context、MCP 和 HTTP GET 使用 SQLite mode=ro 与 query_only，对象库禁止 put；读取不建目录、建库、迁移或写应用缓存。旧库必须从已有写入入口升级。单次结果共享读取快照，已有事务的生命周期仍归调用方；不把 SQLite 的 WAL 共享索引维护宣称为所有物理文件逐字节不变。
- 决定：MCP 在启动参数固定一个明确项目，五个工具每次核对项目内引用。正文搜索按字面量处理，事件没有统一范围时不猜测范围。模型候选、人工/规则确认、替换与驳回各自保留；scope 所有字段和值完全相等才计算当前采用。未知范围、未知发生时间、同刻不同动作分别输出不确定状态，不按较大的 ID 取胜。
- 决定：occurred_until 限定发生时间，known_until 限定已记录时间，二者需明确时区；审核与替换也按已知截止筛选。未知发生时间保留并标记，无法证明记录时间的条目排除并报告唯一引用数量。状态先按整个符合截止的历史计算，再分页展示版本、范围和来源；超过 20 条状态来源明确 partial，详情从 history 取回。
- 理由：后来补记或修改不能改写「当时已知」。单页、图的 2000 条上限和模型生成顺序都不能决定历史语义。续读可以固定双截止并核对 expected_revision，图变化时重新开始。四个状态轴互不替代，采用不确认目标候选、证据或运行。
- 放弃：查询时自动迁移；按时间接近猜项目/范围/采用；只读首张图计算状态；用记录时间补发生时间；忽略后来修改的记录时间；把文件观察当完整文件内容；读取当前文件修复旧证据。

## 2026-10-10 · stdio 协议与注入边界

- 决定：只提供 search/node/evidence/history/context 的 stdio MCP，不开放网络端口、不执行资料里的命令、不注册人工确认或未定类型的 propose_note。文本结果与工具错误使用 rg-context 包装，源字符串中的尖括号转义，不能关闭外围标记；原文窗口用实际 UTF8 边界、摘要和连续字节偏移，不伪称全文。
- 决定：实现 2026-07-28 的逐请求版本/能力、discover、结果类型和缓存字段，同时兼容 2025/2024 初始化协议。现代请求不能继承先前或旧连接的能力；只有旧协议使用进程初始化状态。stdout 只有单行 JSON-RPC，通知不回包、EOF 退出、坏行和超长请求恢复后续读取。
- 理由：当前官方规范已更新到逐请求方式，仍需供已有客户端读取。依据 [版本与兼容](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning)、[stdio](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio)、[工具与错误](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)、[缓存字段](https://modelcontextprotocol.io/specification/2026-07-28/server/utilities/caching)。官方 Python SDK 2.3.0 的现代和旧协议真实子进程验收加入 CI；只创建合成项目，不改个人客户端配置。
- 放弃：依赖此前现代请求建立隐含会话；仅依据手写请求宣称客户端兼容；重复返回标记文本与同一结构化正文；回显不可信请求和异常原件；未确定 note 类型先注册写工具。

## 2026-10-10 · 有界问答、原文引用与模型解释

- 决定：新增 ask CLI，默认最多 12 条校验过的原文窗口，允许 1–100；本地 retrieve-only 使用只读 Store。复用完整项目、完整范围、双截止和历史审核读取服务；对象名称命中会带入其相关决定，无结构化记录时可按字面量搜原件。原件没有统一范围，显式范围下不补猜归属。
- 决定：检索每次最多检查 200 条匹配记录、每记录 20 个引用，原文后备最多检查 200 条匹配事件；默认每窗口 4000 UTF8 字节，可调到 24000。同一引用去重，多记录共享来源；预览、窗口、缺口和上限显式标记。按整个可见历史算独立状态，驳回和替换可作为历史资料，不成为当前事实。
- 理由：§7.11 要求先检索有限证据再回答，来源窗口必须能按复制原件重新核对。字面量排序可离线工作且不让模型自行探索；有限检索不能保证找齐，因此不以没有命中证明材料不存在。
- 决定：沿用 Worker 的 qa 阶段、权限、默认 128k/4k、提供方完整请求实测、日额度、进程锁、响应缓存和污染/截断丢弃。回答逐条引用本次发送的来源 ID 和逐字引文；从遮盖后的实际输入校验，不允许引用未发送或未遮盖文字。没有可校验证据时零调用，模型执行失败仍保留检索结果。

## 2026-10-10 · 物理文件版本与后台完整摘要
