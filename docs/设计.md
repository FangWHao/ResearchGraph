# ResearchGraph 设计（v3 精简版）

2026-10-13 重写。旧版规格、进度和决定见 `docs/archive/`，旧代码见 tag `v0-full-spec`。

## 一句话

找到本机 Claude Code / Codex 的会话，按项目导入，自动整理成一张**研究时间线**：
每条研究线一条泳道，泳道里有主线和分支，分支可以汇回；每个事件都能点开看原话。

## 三步上手

1. **首次打开**：自动找到 `~/.claude/projects`、`~/.codex/sessions`（WSL 下也找 `/mnt/c/Users/*/` 下的同名目录）。找不到或想加别的目录，手动填路径。填 DeepSeek API Key。
2. **新建项目**：
   - 自动：从发现的工作目录（会话的 cwd）里选一个，这个目录及子目录下的会话全部加入；以后新会话自动加入。
   - 手动：在会话列表里逐个勾选，或者上传 `.jsonl` 会话文件。
3. **自动整理**：显示要发送给模型的字数，确认后开始。完成后显示时间线。之后点“更新”只处理新增内容。

## 时间线

```
            10-01        10-02              10-03
研究线 A ┃ [事件1] → [事件2] → … → [事件] ──→ [事件]
        ┃     ╲                              ↗
        ┃      [事件3] ───────────────→ ─┘        ← 分支：从事件1分出，汇入后面的事件
研究线 B ┃ [事件] → …
```

- 横轴两种对齐方式，顶栏切换：
  - **紧凑**（默认）：按天分段，同一天内按先后和依赖排开，不按真实间隔拉伸。研究活动一阵一阵的，这样最省地方。
  - **真实时间**：横轴是真实时间刻度，可以缩放（1–128 像素/小时）。事件画成线上的点，同一行里放得下才显示标题，其余悬停可见。
- 两种视图，同一份数据：
  - **按研究线**（默认）：泳道 = 研究线，泳道里每个分支一行。
  - **按会话**：泳道 = 会话，看“哪天在哪个会话里做了什么”。
- 事件种类：问题、尝试、发现、决定、产出。颜色只用三个色相（尝试蓝、决定橙、发现青），问题和产出用中性色；五种各有不同形状（空心圆、圆、菱形、方块、星），旁边总有文字，不靠颜色单独区分。
- 打开时自动滚到最新的事件；←/→ 在同一行里切换事件，Esc 关闭面板，+/− 缩放。
- 点开事件：标题、摘要、时间、来自哪个会话，以及引用的原话；可以展开前后上下文。

## 整理流程

1. **解析**：流式读取会话 JSONL，只留下用户和 Agent 的文字；工具调用压缩成一行（命令、改了哪些文件、结果的开头）。跳过思考、压缩回放、系统注入和元数据。遇到不认识的记录类型就计数，不报错。
2. **提取事件**（每个会话分块调用模型）：每块不超过 80,000 字，消息带编号。模型返回事件：种类、标题、摘要、引用的消息编号。编号必须落在本块之内，不合规的事件丢弃。
3. **归入研究线**（整个项目调用一次）：模型把事件分到研究线和分支，并给出分支的分出点和汇入点。程序负责校验：每个事件只出现一次，分支内按时间排序，分出点和汇入点的时间先后必须合理。
4. **增量更新**：会话文件变大就重新解析，只为新消息提取事件；已经放好的事件不移动，只给新事件找位置。
5. **重新整理**：清掉自动生成的结构重来（需要确认），人工改过的内容保留。

## 手动修改

- 事件：改标题、摘要、种类；移到别的研究线或分支；删除。
- 研究线：改名。分支：改名，改分出点和汇入点。
- 改过的东西标记为人工修改，自动整理不会覆盖。

## 规则

- 会话文件只读，从不修改。
- 第一次发送给模型前，必须由用户在界面上确认发送量；没有确认就不调用模型。
- 模型输出被截断（`stop_reason = max_tokens`）就作废：提取时把这一块拆成两半重试，归类时报错。
- 模型调用按请求内容缓存，重试和重新整理不重复付费。
- 服务只监听 127.0.0.1，校验 Host；修改类请求必须带 `X-RG` 请求头。不执行会话中出现的命令。
- API Key 存在数据目录（权限 0600），不写进仓库，不出现在日志里。

## 代码结构

```
rg/config.py    数据目录与设置
rg/sources.py   发现会话目录、读取会话元数据（只读开头和结尾）
rg/parse.py     会话解析与瘦身
rg/store.py     SQLite
rg/model.py     模型调用（DeepSeek 的 Anthropic 兼容接口）
rg/organize.py  提取事件、归入研究线、增量更新
rg/server.py    本机 HTTP 服务与静态页面
rg/cli.py       rg start / rg organize
web/src/        React 界面；layout.ts 是时间线布局（纯函数）
scripts/demo.py 生成合成演示项目，开发界面时用，不调用模型
```
