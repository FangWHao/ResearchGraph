# ResearchGraph 设计（v3 精简版）

2026-10-13 重写。旧版规格、进度和决定见 `docs/archive/`，旧代码见 tag `v0-full-spec`。

## 一句话

找到本机 Claude Code / Codex 的会话，按项目导入，自动整理成一张**研究时间线**：
每条研究线一条泳道，泳道里有主线和分支，分支可以汇回；每个事件都能点开看原话。

## 三步上手

1. **首次打开**：自动找到 `~/.claude/projects`、`~/.codex/sessions`（WSL 下也找 `/mnt/c/Users/*/` 下的同名目录）。找不到或想加别的目录，手动填路径。填 DeepSeek API Key。
2. **新建项目**：
   - 自动：从发现的工作目录（会话的 cwd）里选一个，这个目录及子目录下的会话全部加入；以后新会话自动加入。
   - 手动：在会话列表里逐个勾选，或者上传 `.jsonl` 会话文件。
3. **自动整理**：显示要发送给模型的字数，确认后开始。完成后显示时间线。之后只处理新增内容：打开着的项目自动更新，没打开的项目下次打开时问你要不要更新（见“自动更新”）。

## 主页

打开后先看到主页，不直接进时间线：

- 顶部：日期和一句话（近 7 天几个项目里有几次对话、新增多少关键步骤和里程碑；没有新对话就写最近一次是多久前、在哪个项目），四个数（项目、进行中的研究线、待解决的问题、里程碑），右边是近 12 周每天新增关键步骤的热力图（中性灰阶，悬停看数字）。
- 每个项目一张卡片。头部：名字、工作目录、对话数、最近一次对话，四个数（研究线、关键步骤、里程碑、失败的尝试），“打开时间线”。
- 左边是**项目简报**：一两句话说现在在做什么，然后“最近进展”“待解决”“可能的下一步”。每条后面带依据的步骤（同一天的合成一个小标签，图形表示种类），点了直接跳进时间线、停在那个事件；“待解决”还带所属研究线，点了打开那条研究线。底部写哪个模型、什么时候写的，研究线有新变化时提示；“复制给 Agent”把简报和各研究线的进展复制成 Markdown，开新会话时贴进去；“重新生成”。
- 右边是**研究线**：按最近活动排列，每条线一条迷你时间条，横轴是整个项目的真实时间跨度，灰条是这条线从开始到最后一步，上面按种类画出里程碑（点了跳到它）；状态用形状（圆点进行中、勾已完成、叉已放弃），还在进行但 14 天以上没动的标出天数。下面列最近的 5 个里程碑。
- 地址栏：`#/` 主页，`#p=2` 项目，`#p=2&e=15` 停在事件，`#p=2&t=3` 停在研究线；项目页左上角的标志和房子图标回到主页，浏览器“后退”也能回来。

## 时间线

```
            10-01        10-02              10-03
研究线 A ┃ [事件1] → [事件2] → … → [事件] ──→ [事件]
        ┃     ╲                              ↗
        ┃      [事件3] ───────────────→ ─┘        ← 分支：从事件1分出，汇入后面的事件
研究线 B ┃ [事件] → …
```

- 横轴两种对齐方式，顶栏切换：
  - **紧凑**（默认）：每条研究线（或会话）各自从最左边排起，只看本线内部的先后，线与线之间不对齐日期。第 1 天的方向和第 10 天的方向是平行的，上下并列。同一条线里，分支排在分出点之后，汇入点排在分支之后。卡片上直接写日期。跨研究线的分出和汇入平时不画线，卡片上有个小标记，选中时才画出来。
  - **真实时间**：横轴是真实时间刻度，可以缩放（1–128 像素/小时）。事件画成线上的点，同一行里放得下才显示标题，其余悬停可见。
- 两种视图，同一份数据：
  - **按研究线**（默认）：泳道 = 研究线，泳道里每个分支一行。
  - **按会话**：泳道 = 会话，看“哪天在哪个会话里做了什么”。
- 事件只记三类，对应回头看时关心的三件事：**尝试**（带成败：成功、失败、未定）、**决定**（带理由）、**结果**（关键数字、结论、重要成品）。颜色是三个色相（尝试蓝、决定橙、结果青），形状各不相同（圆、方块、菱形），旁边总有文字，不靠颜色单独区分。旧版本的“问题”只用来显示。
- 卡片高度跟着标题走：按页面实际字体量出标题要占几行（最多三行），同一行的卡片取这一行最长标题的高度，连线保持水平，标题不会被截掉或压出卡片。
- 卡片按种类上色：左边一道种类色，底色混进少量种类色（关键 7%、里程碑 16%、细节 3%，深色主题 12%/20%/5%），文字一律用墨色，对比度实测都在 6 以上。里程碑整圈描边、标题加粗；失败的尝试用种类色虚线框、圆里打叉；细节几乎不着色。事件面板的标题区用同一套颜色。
- 每个事件带重要性：细节、关键、里程碑。顶栏“详略”三档：**里程碑**（默认）只看转折点，**关键**去掉细节，**全部**都显示。每条泳道至少保留它最高的一档，不会整条消失；被藏起来的分出点、汇入点移到同一分支最近的可见事件上；卡片上的“+N”表示这里藏着几个细节。里程碑卡片左边有一道粗线、标题加粗。
- **就地展开**：点卡片上的“+N”，它这一段（同一分支里，到下一张可见卡片为止藏着的事件）往下展开一档，出现在时间线原来的位置；展开出来的卡片底色略深，自己也可能带“+N”，可以一层层往下点（里程碑 → 关键 → 细节）。“−”收起。整条被藏起来的分支挂在它的分出点上，展开分出点时一起出来。点卡片本身打开面板，“这一段的经过”按时间列出这一段，点其中一条会一层层展开到它并选中。搜索结果在当前详略下被藏着时，也是这样展开，不再整体切到“全部”。
- 研究线带状态（进行中、已完成、已放弃）和一段进展叙述，泳道标签和研究线面板里显示；面板里列出这条线的里程碑。
- 紧凑模式打开时停在左上方（各线的起点），真实时间模式打开时滚到最新；底栏“最新”随时跳到最新的事件。←/→ 在同一行里切换事件，Esc 关闭面板，+/− 缩放。
- 点开事件：标题、摘要、时间、来自哪个会话，以及引用的原话；可以展开前后上下文。
- **搜索**（顶栏，快捷键 /）：在事件的标题和摘要、以及所有原话里找，几个词用空格分开时要都出现。时间线上不相关的事件变淡。点原话结果跳到它所属的事件（引用了这条消息的事件，没有就是它之前最近的事件），面板里标出命中的那条。用来回答“当时为什么放弃 X”。

## 整理流程

1. **解析**：流式读取会话 JSONL，只留下用户和 Agent 的文字；工具调用压缩成一行（命令、改了哪些文件、结果的开头）。跳过思考、压缩回放、系统注入和元数据；Codex 在 IDE 里拼进来的当前文件、标签页只留下用户真正的请求。遇到不认识的记录类型就计数，不报错。解析规则改了就加版本号，已导入的会话重新读；消息有变化的会话，自动提取的事件作废、从头再提取。
2. **提取事件**（每个会话分块调用模型）：每块不超过 80,000 字，消息带编号。模型返回事件：种类、成败、关键或细节、标题（14 字内）、摘要（60 字内）、引用的消息编号。编号必须落在本块之内，不合规的事件丢弃。只记试了什么和成败、做了什么决定和理由、得到了什么结果；提问讨论、读代码盘点项目、修环境报错、整理打包备份写文档、图的版式修补都不记或记为细节，尝试和它的结果合成一步。
3. **归入研究线**（每批最多 300 个事件，按时间分批）：模型为每个新事件写一条“放进哪里”（已有分支、已有研究线的主线，或新建的研究线、分支），新建的分支带分出点和汇入点；已经放好的事件不再列出，输出长度只随这一批变。研究线按研究问题分，不按对话分，通常 3 到 8 条。每批只给模型看已经放好的事件和这一批的新事件，不写事件来自哪个对话。程序负责校验：每个事件只出现一次，分支内按时间排序，分出点和汇入点的时间先后必须合理。
4. **合并研究线**（研究线超过 8 条时）：模型看所有研究线的标题、进展、步骤数、时间跨度和代表步骤，提出哪些属于同一个方向；程序把它们并进最主要的那条（原来的主线变成一条分支），事件一个不丢。人工改过的研究线不会被并走。
5. **复审研究线**（每条线一次，线里的事件没变就跳过）：模型看整条线的关键步骤，挑出里程碑（大约每 8 到 15 个步骤一个，最多 12 个），写两三句进展叙述，标出状态。提取时只分关键和细节，里程碑只在这里给，因为只有看到整条线才判断得了“以后讲历史时一定会提到”。
6. **写项目简报**（每个项目一次，用复审研究线的模型）：模型看各研究线的状态、进展叙述、里程碑、最近 6 个关键步骤，以及整个项目最近 15 个失败或未定的尝试，写现在在做什么、最近进展、待解决、可能的下一步，并标出依据的步骤和研究线。程序核对编号，对不上的丢掉；正文里的内部编号去掉、研究线编号换成名字。输入（不含当天日期）没变就不重写。截断或出错时保留上一份并记下错误，同样的输入不再自动重试；主页打开时只为落后的简报补写一次（只对同意过发送的项目），用户点“重新生成”才强制重写，并绕过本地缓存。
7. **增量更新**：会话文件变大就重新解析，只为新消息提取事件；已经放好的事件不移动，只给新事件找位置；归类时模型漏掉的事件先单独再问一次，再漏才由程序放到同一会话最近的事件旁边。
8. **重新整理**：清掉自动生成的结构重来（需要确认），人工改过的内容保留。

## 自动更新

- **打开着的项目**：每 20 秒看一次会话文件的大小和修改时间（不解析、不调用模型）。有新内容，并且会话已经安静了设定的时间（默认 3 分钟），就自动整理新增的部分。对话还在进行时不打断。
- **没打开的项目**：后台不更新。下次打开时，如果离开期间有新内容，顶部提示“离开期间有新内容”，选“更新”或“稍后”；也可以在设置里改成直接更新。点了“稍后”，这次打开页面期间不再自动更新这个项目，点“更新”恢复。
- **约束**：只对已经同意过发送的项目生效；一次的新内容超过单次上限（默认 20 万字）时停下来问；整理出错后不自动重试，等用户处理。
- 更新完成后底部提示“新增 N 个事件”，新事件的卡片上标“新”，点“查看”跳到最新的一个。

## 模型

- 三类任务分开选模型和思考强度：**提取关键步骤**（每段对话一次，调用最多）、**归入研究线**（每批新事件一次，含合并研究线）、**复审研究线**（每条线一次）。
- 模型列表从接口读：先试 Anthropic 的 `/v1/models`，DeepSeek 的 `/anthropic` 下没有，就读同一服务的 `/models`，那里带上下文长度、最长输出和支持的思考强度（低、高、最高）。读不到时可以手动填写模型名。
- 思考：DeepSeek 打开思考时不能强制调用工具，所以改成让模型自己调用 submit（不调用就当格式错误重问），并在 max_tokens 上额外预留思考的 token（低 8000、高 24000、最高 48000；模型的思考常常超过给它的预算）。缓存按模型和思考强度区分。
- 推荐设置（新装时的默认值）：提取用 deepseek-flash、思考“高”；归类和复审用 deepseek-v4-pro、不思考。归类打开思考后输出总被截断，失败时提示去设置里调低。理由见 DECISIONS。
- “检测这些模型”给每个选中的模型各发一条 1 token 的消息；用量页按模型列出调用和 token。

## 设置

- **常规**：会话目录；模型（Key、检测、接口和模型名）；自动更新（开关、安静多久、单次上限、打开项目时先问还是直接更新）。
- **用量**：每次调用模型都记下 token（输入、输出、命中服务端缓存的部分），命中本地缓存的请求记一笔但不算 token。按今天、近 7 天、近 30 天、全部汇总，画近 30 天每天的柱状图，并按项目、按步骤（提取关键步骤、整理研究线）列表。删掉的项目，用量仍算在总数里。

## 手动修改

- 事件：改标题、摘要、种类；移到别的研究线或分支；删除。
- 研究线：改名；并入另一条研究线（它的主线成为对方的一条分支）。分支：改名，改分出点和汇入点，删除（事件并入同一研究线排在最前的分支）。
- 改过的东西标记为人工修改，自动整理不会覆盖。

## 项目设置

- 改名；跟随工作目录的开关。
- 会话：列出项目里的会话，可以移出（它的消息和事件一起删掉，会话文件不动；跟随工作目录时也不会再自动加回来）；可以从已发现的会话里添加，或上传文件。
- 已删除的事件：可以恢复，回到原来的分支；原分支已经没了，就跟着同一会话里最近的事件走。

## 规则

- 会话文件只读，从不修改。
- 第一次发送给模型前，必须由用户在界面上确认发送量；没有确认就不调用模型。
- 模型输出被截断（`stop_reason = max_tokens`）就作废：提取时把这一块拆成两半重试，归类时报错。
- 模型调用按请求内容缓存，重试和重新整理不重复付费。
- 服务只监听 127.0.0.1，校验 Host；修改类请求必须带 `X-RG` 请求头。不执行会话中出现的命令。
- API Key 存在数据目录（权限 0600），不写进仓库，不出现在日志里。

## 代码结构

```
rg/config.py    数据目录与设置
rg/sources.py   发现会话目录、读取会话元数据（只读开头和结尾）
rg/parse.py     会话解析与瘦身
rg/store.py     SQLite
rg/model.py     模型调用（DeepSeek 的 Anthropic 兼容接口），报告每次的 token
rg/usage.py     记录和汇总模型用量
rg/organize.py  提取事件、归入研究线、增量更新
rg/brief.py     项目简报（写、核对、存）和主页汇总
rg/server.py    本机 HTTP 服务与静态页面
rg/cli.py       rg start / rg organize
web/src/        React 界面；Home.tsx 是主页；layout.ts 是时间线布局，auto.ts 是自动更新的判断（都是纯函数）
scripts/demo.py 生成合成演示项目，开发界面时用，不调用模型
```
